# V1.2 程序整改交付记录

依据：测试用例 V2 的 95 项与需求规格说明书 5.6.5。本轮只修复此前已确认的程序实现缺口；95 项完整测试由后续独立轮次执行，不能把本记录当作测试通过结论。

## 修复

- TC-082 航班变更部分渠道不可用：计划仍保留航延屏、智慧航显和机器人等要求的渠道步骤。至少一个正确物理类型的发布渠道可用时，缺席渠道在执行分配阶段记 `SKIPPED`、原因码 `FLIGHT_CHANNEL_UNAVAILABLE`，输出 `UNCOVERED` 并追加事件；其余可用渠道继续执行。没有任何发布渠道完成时转 `PENDING_MANUAL`，不报任务完成。
- 候选设备全部拒绝、设备执行失败、试运行未成功以及未知能力继续走原有失败或人工处理闸门；部分渠道规则不将这些情况视为成功，也不向错误设备类型或未在线空闲设备下发命令。
- 航班任务详情显示各渠道“已完成/未覆盖”以及反馈完成时间、响应时长，便于 V2 逐步核对。

## 定向检查

- 后端 `CoreScenarioChannelPolicyTest` 和 `FlightPartialChannelExecutionTest` 共 7 项通过：覆盖部分渠道可用、无发布渠道、未知能力、缺少计划步骤、跳过不可用渠道、无渠道不得完成、可用智慧航显仍进入真实承接请求；无完整 95 项测试。
