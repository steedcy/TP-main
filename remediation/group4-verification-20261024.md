# 第四组设备页面与非功能：阶段检查点（2026-10-24）

状态：**未完成验收，不发布 V1.04**。

## 根因与改动

- TC-070/071：态势页原来按左下角原点翻转 Y，且无设备类型筛选、能力摘要和当前任务链接。改为与用例一致的左上角像素坐标；五类设备默认全选，仿真体可按本体或模拟类型筛选；无有效坐标设备只在列表展示，离线设备保留位置和灰色标记；详情显示已启用能力及有权限角色的当前任务链接。底图尺寸实际为 1260×6895 像素，更换底图需要重新标定。
- TC-089：任务详情原来只对执行中、降级中和监督中状态轮询。现在所有可处置活动状态均每 10 秒刷新。
- TC-090：设备档案表单弹窗加入视口内滚动，适配 1366×768。尚缺实际 Chrome/Edge 双浏览器和两分辨率取证。
- 登录失败：拦截器原来将登录接口返回的 401 在登录页静默处理。现对 `/auth/login` 单独显示统一错误提示，同时空白账号/密码不能启用提交按钮。

## 回归证据

- [态势接口实测](evidence/group4-situation-20261024.json)：22 个对象可从配置管理员与运行操作员读取；六个 F2 仿真体有已启用能力摘要且坐标落在底图范围；接口声明 5 秒刷新。25 次顺序请求中位数约 116ms、p95 约 173ms。该样本无 20 对象持续上报或任务并发负载，不是 TC-089/性能验收结论。
- 浏览器本地登录页：虚构不存在账号及虚构密码，首次观察到 401 静默问题；修复后页面显示“账号或密码错误”。Windows Computer Use 随后因无法可靠确认 Chrome 当前 URL 而停止；未继续操作 Chrome/Edge。
- 后端 `mvn test -q`：61 tests，0 failures，0 errors，1 skipped；态势接口单测覆盖能力摘要。
- 前端 `npm run build`：通过，仍有包体积警告。
- 六个 F2 代理在回归后均为 `ONLINE/IDLE`、当前任务指针为空；三套预置基线模板为 `ENABLED`。这只覆盖当前状态，不代表设备生命周期全路径已通过。

## 未验收与回滚

- TC-089 的 20 对象按 15 秒实际持续上报、任务详情相邻刷新时间需补测；NF 页面 p95 需在 10 用户、10 并发任务和 20 对象负载下采样；8 小时稳定性需待三场景冒烟与版本/模板冻结后运行。
