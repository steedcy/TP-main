# 第三组补充：F2 标准演示数据复位（2026-10-24）

状态：**隔离环境功能验证通过；TC-006/007 尚待公司版人工签认，不发布 V1.03**。

## 固定数据集与安全边界

- 用户确认先以 `scripts/test-fixtures` 的 F2 虚构数据定义可复现标准集。资源固定在 `backend/src/main/resources/demo-f2/`：六个设备及 17 项能力、三套预置基线、三类预置任务定义。版本 `F2-DEMO-20261024`，源文件 SHA-256 与生成时间在管理员预览页展示。
- 影响范围仅包括上述六个 `SIM_F2_*` 设备档案及其能力、三套预置模板和三类任务定义。其他设备、历史任务及事件、账号、设备令牌和既有凭据标识保留。
- 复位后设备连接和能力状态为 `UNTESTED`，基线模板为 `DRAFT`，任务定义为 `ENABLED`。重新连接测试、能力测试、模板试运行并启用后才能再次运行场景，复位不伪造测试通过状态。
- 复位接口默认关闭，仅隔离演示环境显式设置 `DEMO_RESET_ENABLED=true` 后可写入。系统管理员可预览版本、摘要、影响范围和阻断清单；须输入完整确认短语并在二次弹窗确认。后端也校验两项。
- 事务开始后锁定任务表，拒绝存在五类活动任务或忙碌 F2 代理的复位；数据更新与成功审计在同一事务中。失败在事务回滚后另记失败审计，含操作者、时间、版本、摘要、耗时及原因。

## 实测

[隔离原始证据](evidence/group3-reset-isolated-20261024.json) 使用 PostgreSQL `tip_f2_reset_20261024` 独立 schema，Flyway V1–V16。独立数据库创建权限不足，已用独立 schema 隔离；共享业务 schema 未作复位。

- 集成测试 1/1 通过，0 失败、0 错误。分别准备 `PLANNING`、`SUPERVISING`、`PENDING_ASSIGNMENT`、`DOWNGRADING`、`EXECUTING` 任务，五次均拒绝且业务摘要不变。
- 错误确认短语拒绝且业务摘要不变。中途注入异常后，设备、能力、模板和定义回滚到**本次复位前的已修改状态**，失败审计留存。
- 正常复位与重复复位的业务摘要一致：`6fca6554ee3afa909f3a85de31988e004d77a21db7359829be25da1be331ab30`。六设备、17 能力、三草稿基线、三启用任务定义；成功及失败审计均可查，成功记录包含耗时。
- 共享测试环境的六个 F2 代理在隔离测试后仍在线空闲、无当前任务指针。
