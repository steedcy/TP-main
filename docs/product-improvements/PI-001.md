# 设备令牌与仿真体自动接入（2026-11-13）

本次为用户直接要求的增量功能，实现与当前独立验收分开；不改写历史 P/F/NT。

验证范围见[产品改进检查项](PI-001-checks.md)。

- 新建设备时，在同一事务中生成独立随机访问令牌，数据库仅保存 SHA-256 摘要与 AES-GCM 密文。缺少 `DEVICE_CREDENTIAL_ENCRYPTION_KEY` 时整次新增回滚。
- 新建本机仿真体后异步下发令牌并启动进程，重试时重启本服务管理的对应进程；健康握手通过才创建/绑定唯一代理，收到本次绑定后的真实心跳才显示接入完成。能力仍须测试才能启用。
- 新建仿真体可留空接入地址和凭据标识，系统分配本机 18100～18199 空闲端口及令牌引用。真实设备仍须填写这两个字段。
- 设备列表提供自动接入状态、失败原因、重试及访问令牌轮换入口。轮换后的明文只在本次响应中提供，关闭弹窗即丢弃。仿真体轮换后自动重启接入；有进行中任务时拒绝重启/轮换。
- 仅管理本机 HTTP 根地址，不能接管已经占用端口的外部进程；不会按端口杀进程。远程设备需独立部署管理器，当前明确报错并允许人工配置后连接测试。
- 启动前在 `simulator` 目录执行 `mvn package`；可设置 `DEVICE_SIMULATOR_JAR` 指向绝对 JAR 路径。默认自动寻找仓库 `simulator/target/device-simulator-runtime.jar`。`DEVICE_SIMULATOR_MANAGEMENT_ENABLED=false` 可关闭进程管理。
- 后端通过 `ProcessBuilder` 直接运行 Java，不经过 shell；令牌不进入命令行或配置文件。子进程仅继承必要操作系统变量，不继承数据库/模型凭据。日志位于忽略目录 `.local-test/managed-simulators/`。
- 后端正常关闭时停止自己启动的仿真体；再次启动后可用“重试自动接入”恢复。崩溃遗留的外部进程不会被自动终止，需要运维核对后处理。删除设备后释放本服务管理的进程。

验证方式：`python scripts/verify-device-onboarding.py --backend-tests` 在专用 PostgreSQL schema 执行后端全量测试与打包（旧观测性测试关闭 Flyway，因此先按顺序执行迁移）；`python scripts/verify-device-onboarding.py` 在另一专用 schema、18380 端口及 Redis DB 15 运行真实 HTTP/SQL/子进程闭环。两者均不操作 public 表、不清空 Redis、不停止外部进程。`--quick` 仅用于调试单驱动，正式增量验证使用不带此参数的四驱动轮次。结果位于忽略目录 `.local-test/onboarding-smoke/`，逐轮结果按 schema 保留。

已发现并修正的实现问题：新增控制器依赖须补入原 WebMvc 安全测试；连接就绪探针须经过既有 DeviceService 适配入口；Windows 终止自有进程后立即探测端口会将短暂残留误判为其他进程，现按进程所有权与原端口决定重启路径，由新 JVM 执行实际绑定，外部端口继续执行占用检查。原始诊断和更正结果保留于本地，未修改历史 stage3 失败登记。

2026-11-14 最终实现验证：后端全量 620 项（618 通过、2 原有跳过、0 失败/错误）及生产 JAR 打包通过；仿真模块 29 项全部通过并打包；前端生产构建通过。四驱动真实子进程/HTTP/SQL闭环共13组观察全部通过，包含自动签发与心跳、两个连续轮换与旧令牌失效、代理编号复用、忙碌/权限保护、外部端口保留与释放后重试、远程明确失败、真实设备仅签发令牌。脱敏结果见 `docs/product-improvements/evidence/device-onboarding-implementation-20261114.json`。首次全量回归的观测性测试因未迁移的旧库缺新列而报前置错误，最终轮次改用完整迁移后的专用 schema；没有为此修改共享库或放宽断言。

首次交付为源代码改动，当时未替换运行服务。生效前须重新构建 `simulator` 与 `backend` 并重启后端；前端使用生产部署时也须发布新的构建产物。现有 `docs/HANDOFF.md`、产品版本标签与独立验收台账保持其原状态。

2026-11-14 按用户后续明确授权完成本机启用：后端、仿真模块和前端重新构建；后端 8080 与前端 5173 已启动，数据库 public 从 V30 非破坏性迁移至 V31（迁移前本地备份保留于忽略目录）。7 台启用仿真体均由后端管理器启动，连接测试通过且已收到新心跳；原有 6 个代理编号保留，原先缺令牌的 `SIM_F2_DISPLAY_B` 自动签发令牌并创建代理。前端新入口及 API 代理已核验，启动脚本退出后服务持续运行，原任务数量不变。脱敏记录：`docs/product-improvements/evidence/device-onboarding-local-activation-20261114.json`；此记录为本机部署启用结果，不代替独立需求验收。
