# PI-007：规划模型主备切换、空间规则对齐、标准演示数据集固化与容器化部署（V1.5）

- **状态**：已完成并归档
- **产品版本**：**V1.5**

## 1. 改进原因

1. 外部规划模型需支持主备自动故障切换与系统管理员手动路由切换，提升规划服务可用性。
2. 航站楼 2000×600 室内地图、20 台仿真体设备、附录 F 能力契约、4 类预置场景（含通用协同服务 `GENERAL_SERVICE`）及空间隔离/距离校验/风险规则完成全面重构后，原标准演示数据复位仍停留在旧版 F2 6 台设备口径。
3. 测试环境需要面向 CentOS 7 / Ubuntu 24.04 的 Docker Compose 容器化部署与版本增量更新/回滚能力。

## 2. 主要改动

### 2.1 规划模型主备双活与手动切换
- 新增 `PlanningChatClient`、`ClaudeChatClient`、`FailoverChatClient`、`PlanningModelConfigController`、`PlanningModelConfigService`，支持 `AUTO_FAILOVER`（主模型 1003/1004 不可用时自动切换至第二模型，内容不合规 1002 不切换）、`PRIMARY_ONLY`、`SECONDARY_ONLY` 三种模式。
- 默认规划模型配置已设为 **仅使用第二模型 `gpt-sonnet-6.1`（`SECONDARY_ONLY`）**，并在 `application.yml`、`docker-compose.yml` 与 `PlanningModelConfigView.vue` 中统一对齐；新增 Flyway 迁移 `V45__default_planning_model_gpt_sonnet_6_1.sql`，升级已有环境时自动将 `system_settings` 中的运行模式与模型名切换为 `SECONDARY_ONLY` / `gpt-sonnet-6.1`（保留既有 API Key 与 Base URL）。
- 前端新增系统管理员配置页 `PlanningModelConfigView.vue` 及导航/路由入口，实时展示当前生效模式、首选模型与最近一次调用状态。

### 2.2 2000×600 室内地图、20 台仿真体与空间/风险规则对齐（Flyway `V34` ～ `V44`）
- **数据库迁移 `V34`～`V44`**：重建 2000×600 矢量地图区域（18 条）与设施点位（68 个，含 V43/V44 商业/设施带点位）；清理旧 `SIM_F2_*` 仿真体，统一 20 台新仿真体命名、附录 F 能力边界、`test_passed=TRUE` 与隔离区内外归属；对齐三类标准基线模板、新增第 4 类场景 `GENERAL_SERVICE`（通用协同服务），并将 `RULE_RESOURCE_CRITICAL` 调整为“可用候选设备数量 > 0”。
- **校验与风险逻辑**：`PlanValidationService` 新增 `checkSpatialMapConstraints`（点位存在性、禁行区拦截、固定设备 650 / 移动机器人 1600 最大服务距离）；`RiskAssessmentService` 结合地图 POI 坐标完善 `hitsCrossZone` 跨隔离区判定并同步更新 `RULE_RESOURCE_CRITICAL` 阈值（默认 `0`）；新增 `TerminalLocationNormalizer`；同步更新 `MobileRobotDriver` 导航/陪同路由与前端地图/设备/任务视图。

### 2.3 V1.5 标准演示数据集全面固化与复位重构
- 全面替换 `backend/src/main/resources/demo-f2/` 资源文件并新增地图区域/点位、风险规则与校验规则基线文件：
  - `map-regions.json`（18 条区域与走廊）
  - `map-pois.json`（68 个最新设施点位）
  - `devices.json`（20 台仿真体设备及对齐附录 F 的启用能力）
  - `baselines.json`（3 套 V1.5 已启用标准基线模板）
  - `scenarios.json`（4 类预置场景规则：超规行李、特殊旅客、航班变更、通用协同服务）
  - `risk-rules.json`（3 条最新风险规则）
  - `validation-rules.json`（空间隔离与服务距离等校验规则基线参数）
- 重构 `DemoDataset`（版本 `V1.5-DEMO-20261126`）、`DemoResetWorker` 与 `DemoResetService`：执行标准数据复位时自动清理旧 `SIM_F2_*` 遗留数据，事务级原子恢复全部地图、点位、20 台仿真体与能力/代理、基线模板、4 类场景、风险规则及校验规则配置。

### 2.4 容器化部署与运维脚本体系
- 新增 `docker-compose.yml`、`.dockerignore`、`docker/` 构建定义（含免依赖预编译 `Dockerfile.prebuilt`），以及 `scripts/docker-deploy.sh`、`scripts/docker-update.sh`、`scripts/docker-start-simulators.sh`、`scripts/package-docker-prebuilt.ps1`、`scripts/deploy-ubuntu24.sh`、`scripts/start-all.*`、`scripts/package-local-bundle.ps1`；支持本机预编译成品包，服务器端更新跳过 Maven/npm 依赖下载与编译，并支持自动拉起容器内所有仿真体。
- 补充 CentOS 7 / Ubuntu 24.04 部署与测试服务器增量更新手册（`docs/CENTOS7_QUICK_START.md`、`docs/CentOS7测试环境Docker部署文档.md`、`docs/Ubuntu24.04测试环境部署文档.md`、`docs/测试服务器版本更新部署手册.md`）。

### 2.5 仿真控制三类端到端演示预置数据对齐
- 更新 `SimulatorConsoleView.vue` 与 `TaskListView.vue`：将航变旅客坐标范围对齐为 `2000×600`（默认 `(896, 435)`），将行李测量事件表单与预设示例（`MEASURE_WEST` / `MEASURE_EAST` / `OVERSIZE_CHECKIN`）以及航班变更、超规行李处置、特殊旅客陪同三类端到端演示任务（`GATE_04` / `MEASURE_WEST` / `OVERSIZE_CHECKIN` / `SERVICE_DESK`）全部更新为最新地图与设施点位。

### 2.6 设施矩形区域、空间配置统一、规则与协同陪同动画优化（`V46`）
- **互不重叠的设施矩形区域（`V46__poi_bounds_and_rule_updates.sql`）**：为 `terminal_pois` 增加 `bounds_json` 并为全部 68 个设施点位生成互不重叠的矩形边界；灰色设施带内上排北边与候机区相接（`y1=235`）、下排南边与值机区相接（`y2=341`），保持中间分隔带不可穿行、必须经安检跨区，同时使所有设施明确归属隔离区内/外。前端 `IndoorMapEditor.vue` 同步渲染各设施矩形区域。
- **停用固定降级规则**：在 `V46` 与 `demo-f2/risk-rules.json` 中停用 `RULE_ESCORT_SPECIAL_PASSENGER`，避免特殊旅客场景下大模型自主规划结果被 100% 强制基线降级丢弃。
- **统一空间配置与同机器人绑定**：新增 `SpatialRuleConfig.java` 统一从 `system_settings`（优先）和 `application.yml`（回退）读取 `fixedDeviceStrictZone` / `fixedMaxServiceDistance` / `robotMaxServiceDistance` 与矩形区域隔离判定；在 `baselines.json`、`V46` 及 `TaskExecutionOrchestrator` 中要求特殊旅客第 2 步 `CAP_NOTIFICATION` 与第 3 步 `CAP_NAVIGATION`、第 4 步 `CAP_ESCORT` 使用同一台移动服务机器人，并将运行时距离基准统一对齐校验阶段锚点规则。
- **任务看板同步陪同动画优化**：将 `SimulatorProperties.minRouteDurationMs` 从 `0` 调整为 `6000ms`（24 航点每 250ms 上报），`TaskBoardView.vue` 缩短执行中轮询至 `350ms`、扩展实时/回放模式下的机器人与旅客同步跟随移动，`IndoorMapEditor.vue` 增加 `0.35s linear` 位移平滑过渡。
