# Kimi 规划模型服务接入核查报告

核查日期：2026-10-22（Asia/Shanghai）。

需求范围仍以用户指定的 V1.0 需求规格说明书、30 项功能需求、18 项非功能需求和 95 项测试用例为准。本报告记录模型服务接入与开测准备证据，不代表上述需求或用例已验收通过。

## 1. 核查结论

系统级 `MOONSHOT_API_KEY` 已存在，且已通过 Kimi 官方服务实际认证和生成调用。Kimi 可以作为本项目目标理解与候选计划生成的推理服务。已补充后端适配与启动环境读取，选择本账号实际可用的 `kimi-k2.6`。

当前状态为：**API 接通、适配层已落地、虚构数据接口探测成功；业务执行链路及完整测试准备尚未完成。**

无需再提供另一家模型平台的密钥，也无需为现有后端本地监督规则另行提供模型密钥。模型效果、输出可执行性、稳定性、并发和长期响应时间仍待实际用例验证。

## 2. 密钥、模型和环境证据

| 检查 | 实际结果 | 证据边界 |
|---|---|---|
| Windows 系统级密钥 | 已发现 `MOONSHOT_API_KEY` | 未输出或写入报告/源码中的密钥值 |
| 原客户端进程环境 | 原先未继承新密钥变量 | 启动脚本现会在变量缺失时读取 Windows 用户级/系统级配置 |
| 官方模型列表接口 | 实际认证成功 | 返回 `kimi-k2.7-code`、`kimi-k2.6`、`kimi-k3`、`kimi-k2.7-code-highspeed` |
| 默认接入模型 | `kimi-k2.6` | 使用非思考模式及 JSON Object 输出；可配置模型名，切换后需重新验证参数兼容性 |
| 基础地址 | `https://api.moonshot.cn/v1` | 目标接口为 `/chat/completions` |
| 后端启动 | 已重新启动，健康接口返回 UP | 不等同于有设备参与的完整业务已通过 |

已设置的 Windows 用户级非敏感变量为：`PLANNING_MODEL_PROVIDER=moonshot`、`MOONSHOT_MODEL=kimi-k2.6`、`MOONSHOT_BASE_URL=https://api.moonshot.cn/v1`。密钥继续保留在原有系统级变量中。

从项目根目录运行 `scripts/start-backend.ps1` 即可加载配置。若使用 IDE 等方式启动，需要让相应进程继承上述变量。旧的外部自定义模型服务可通过 `PLANNING_MODEL_PROVIDER=external` 继续选择；Kimi 适配不要求把官方 API 错配为项目自定义的 `/v1/goal/understand` 或 `/v1/planning/generate` 地址。

## 3. 已落地的适配

- `MoonshotChatClient` 调用官方接口，从模型响应的 `choices[0].message.content` 读取最终 JSON；不把推理内容当作业务响应。
- `MoonshotModelService` 实现既有的 `GoalUnderstandingService` 和 `PlanningModelService`，将返回结果转换为平台现有字段。
- 提交给模型的任务族来自数据库当前启用的任务定义，未把预置三类任务族硬编码为唯一范围。
- 检查缺失字段、布尔/数组类型、任务族一致性、完整性与补充问题的一致性、计划步骤基本结构及置信度范围。
- 设置 60 秒请求超时和输出 token 上限；不自动重试。空响应、截断、错误 JSON、HTTP 错误、超时均走失败返回。
- 模型适配层只生成候选数据，未增加直接下发设备命令的入口。现有平台计划校验和监督仍负责后续流转。

## 4. 实际验证记录

### 4.1 真实在线调用

在线探测只使用虚构航班、虚构区域和固定测试定义，未读取真实旅客资料，未创建任务、写入业务数据库或下发设备命令。

| 探测 | 结果 | 耗时 | 证明的内容 |
|---|---|---:|---|
| 最小 JSON 响应 | 成功 | 1.138 秒 | 密钥、网络、模型权限和当前生成额度可用 |
| 目标理解 | 协议检查通过 | 3.872 秒 | 返回合法目标解析字段和已有任务族编码 |
| 缺失信息追问 | 协议检查通过 | 2.458 秒 | 缺少航班号时返回 `infoComplete=false` 及补充问题 |
| 候选计划生成 | 格式及基本能力类型检查通过 | 11.320 秒 | 返回候选步骤、解释、置信度和候选差异标记 |

4 次生成调用记录用量合计 2192 tokens（输入 1614、输出 578）。这是本次少量探测的用量，不是正式测试费用或全部测试预算估算。

证据：`test-evidence/20261022-moonshot-readiness.json`。其中保留虚构数据的实际适配结果；三个 `passed` 字段仅指该探测定义的接口格式与基本内容断言。

## 5. 已观察到的限制与剩余工作

| 项目 | 证据与状态 | 下一步与判定标准 |
|---|---|---|
| 规划输出业务语义 | 实际样例除发布步骤外，还生成一个“确认发布状态”步骤，并使用 `checkContent` 参数；探测未配置实际设备能力的入参 schema | 结合真实登记能力的入参定义核验、约束模型输出；不得把格式正确等同于步骤可执行。未通过参数和能力校验的计划不得进入设备执行 |
| 局部重新规划输入 | 当前 `ReplanningService` 将场景参数设为空，且未设置模型请求的 `capabilityContext`；本次未修改这段业务链路 | 补齐来自原任务及新快照的上下文，并验证保留已完成步骤、剩余额度和失败分支，不能仅凭首次规划探测推断重规划已通过 |
| 四类仿真体 | 实际数据库设备、代理、设备能力记录均为 0；8091–8094 未监听 | 创建四类仿真体档案，配置独立设备凭据、实际能力及其参数、区域与坐标；启动并完成连接测试和代理绑定，验证在线上报与命令回执 |
| 基线模板 | 数据库三个模板均为 DRAFT，步骤数组为空 | 按既有用例和需求补充场景、步骤及参数映射，完成相应试运行/启用前置条件；检查降级执行链路 |
| F2 态势联动 | 底图资源及平移缩放、坐标换算代码存在；当前无实际登记代理 | 验证四类仿真体位置、状态刷新和离线恢复；底图构建成功不代替状态链路验证 |
| 异常路径 | 本次仅模拟检查适配层错误处理，未对实际模型平台或设备执行故障注入 | 在受控环境验证超时、限流、格式错误、设备离线、执行失败等用例前置条件；不得用生产平台随机故障代替可重复的故障条件 |
| 非功能要求 | 少量顺序请求耗时低于 60 秒 | 不能推断 18 项非功能需求均已满足；按原用例测量并发、响应、可靠性、安全和日志等要求 |
| 正式开测 | 95 项正式用例未执行 | 补齐环境与场景后，按用户要求再次核对开测条件；实际日期写入测试记录，保留每项通过/失败/阻塞证据 |

上述设备、模板、测试数据及故障准备可继续基于已提供的账号文档、F2 底图及虚构数据授权完成。API 方面目前没有需用户再提供的缺失密钥；正式持续调用期间仍需保持账号余额与调用配额可用。
