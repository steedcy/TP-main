# 智慧机场人工智能集群协同服务平台 — CentOS 7 测试服务器版本更新部署手册

**适用系统**: CentOS 7.x (x86_64)  
**部署架构**: Docker Compose 容器化部署（PostgreSQL 15 + Redis 7.2 + 后端单体应用含仿真运行时 + Nginx 前端）  
**适用场景**: 测试服务器已完成首次部署，后续程序代码、数据库迁移脚本（Flyway `V*.sql`）或预置演示数据集更新后的增量升级、验证与回滚。  
**关联文件**:
- 首次部署文档：[CentOS7测试环境Docker部署文档.md](./CentOS7测试环境Docker部署文档.md)
- 一键更新与回滚脚本：[scripts/docker-update.sh](../scripts/docker-update.sh)

---

## 1. 版本更新核心原则（必读）

1. **严禁覆盖或重置 `.env` 环境密钥文件（切勿使用 `--force-env`）**
   - `/opt/airport-ai/repo/.env` 中保存了当前数据库的访问密码以及 `DEVICE_CREDENTIAL_ENCRYPTION_KEY`（设备凭据 AES 加密主密钥）。一旦重置，会导致新容器无法连接已有数据库，或已接入设备的加密凭据无法解密。
2. **先备份数据库，再启动新版本后端**
   - 后端容器启动时 Flyway 会自动检测并执行新增的 `V<N>__*.sql` 迁移脚本。由于 Flyway 不支持自动向下回滚（Downgrade），升级前必须先使用 `pg_dump` 备份数据库。
3. **清理旧代码目录后再解压新包**
   - 更新源码时应先清空 `/opt/airport-ai/repo` 中除 `.env` 以外的旧文件再解压新包，避免旧版本已删除或重命名的源文件、迁移脚本残留在目录中引发构建或启动冲突。
4. **保持 `/opt/airport-ai/repo` 目录路径不变**
   - Docker Compose 默认以所在目录名（`repo`）作为项目名来绑定容器与数据卷（`repo_postgres_data`、`repo_redis_data`）。更新时必须仍在原 `/opt/airport-ai/repo` 目录下操作。

## 2. 本地打包与上传（Windows 开发机操作）

在 Windows 本机打开 PowerShell 并进入项目根目录，根据发布场景选择以下一种方式打包并上传至 CentOS 7 测试服务器：

### 方式 1：按已提交的 Git 版本标签打包（推荐，版本严格可追溯）
当新版本已完成 Git 提交（或打上如 `V1.200` 的版本标签）时，使用 `git archive` 可确保不会混入本地未提交的临时文件：

```powershell
# 在项目根目录执行（可将 HEAD 替换为具体的版本标签，如 V1.200）
mkdir -Force outputs | Out-Null
git archive --format=tar.gz -o outputs\airport-ai-src.tar.gz HEAD

# 上传至 CentOS 7 测试服务器 /tmp 目录
scp outputs\airport-ai-src.tar.gz root@<服务器IP>:/tmp/
```

### 方式 2：包含本地当前工作区未提交改动直接打包（用于快速联调验证）
若本地有尚未提交的代码修改需要直接发往测试服务器验证：

```powershell
mkdir -Force outputs | Out-Null
tar --exclude=.git --exclude=node_modules --exclude=target --exclude=.local-test --exclude=document --exclude=acceptance --exclude=outputs -czf outputs\airport-ai-src.tar.gz .

# 上传至 CentOS 7 测试服务器 /tmp 目录
scp outputs\airport-ai-src.tar.gz root@<服务器IP>:/tmp/
```

## 3. CentOS 7 服务器端一键自动化更新（推荐）

项目已内置一键更新与回滚脚本 `scripts/docker-update.sh`，会自动完成 **数据库 `pg_dump` 备份 -> 旧代码与旧镜像打标备份 -> 保留 `.env` 清理并解压新源码包 -> 重新构建并滚动更新容器 -> 清理悬空旧镜像 -> 健康检查验证** 全流程。

### 3.1 执行一键更新命令

登录 CentOS 7 测试服务器终端，执行以下单条命令即可完成更新：

```bash
# 若服务器上已有 scripts/docker-update.sh，直接执行：
sudo bash /opt/airport-ai/repo/scripts/docker-update.sh --src /tmp/airport-ai-src.tar.gz
```

> **提示**：如果是**首次**使用该更新脚本（服务器上旧版本代码中还没有 `scripts/docker-update.sh`），可先从新上传的压缩包中提取该脚本再运行：
> ```bash
> tar -xzf /tmp/airport-ai-src.tar.gz -C /tmp scripts/docker-update.sh
> sudo bash /tmp/scripts/docker-update.sh --src /tmp/airport-ai-src.tar.gz
> ```

### 3.2 `scripts/docker-update.sh` 常用参数说明

| 命令 / 参数 | 说明 |
|---|---|
| `sudo bash scripts/docker-update.sh` | 默认读取 `/tmp/airport-ai-src.tar.gz` 并自动从 `.env` 识别服务器 IP 完成一键备份与更新 |
| `--src <路径>` | 指定新版本源码包路径（默认 `/tmp/airport-ai-src.tar.gz`） |
| `--load-images <路径>` | 使用离线镜像包一键备份并更新（免 Maven/npm 源码编译，适合内网隔离服务器） |
| `--server-ip <IP>` | 显式指定服务器访问 IP（默认自动从 `.env` 或网卡提取） |
| `--list-backups` | 列出 `/opt/airport-ai/backup` 下所有历史备份的时间戳、数据库备份大小与代码备份目录 |
| `--rollback <时间戳>` | 一键回滚到指定时间戳版本（自动恢复旧代码、还原数据库 `pg_restore` 并切回旧镜像启动） |
| `--skip-db-restore` | 配合 `--rollback` 使用，回滚时仅恢复旧代码与容器，不覆盖当前数据库数据 |

## 4. 手动分步备份与更新命令（备查）

如果不使用 `scripts/docker-update.sh` 一键脚本，也可以在服务器终端按顺序手动执行以下等效命令：

```bash
# 1. 定义本次更新时间戳并创建备份目录
TS=$(date +%Y%m%d_%H%M%S)
mkdir -p /opt/airport-ai/backup
cd /opt/airport-ai/repo

# 2. 加载当前环境变量并备份 PostgreSQL 数据库（自定义压缩格式，支持 pg_restore）
set -a && source .env && set +a
docker compose exec -T postgres pg_dump -U "$DB_USERNAME" -d "$DB_NAME" -Fc \
  > "/opt/airport-ai/backup/db_${TS}.dump"

# 3. 备份当前运行的代码目录（含 .env）
cp -a /opt/airport-ai/repo "/opt/airport-ai/backup/repo_${TS}"

# 4. 清理旧代码（严格保留 .env 配置文件），然后解压新版本源码包
find /opt/airport-ai/repo -mindepth 1 -maxdepth 1 ! -name '.env' -exec rm -rf {} +
tar -xzf /tmp/airport-ai-src.tar.gz -C /opt/airport-ai/repo

# 5. 执行一键构建与容器滚动更新（注意：切勿添加 --force-env）
cd /opt/airport-ai/repo
sudo bash scripts/docker-deploy.sh --server-ip <服务器IP>

# 6. （可选）清理构建产生的悬空旧镜像，释放磁盘空间
docker image prune -f
```

> **配置项微调说明**：若本次更新需要同步修改 `.env` 中的配置（如更换 `MOONSHOT_API_KEY` 或新增环境变量），请直接编辑 `/opt/airport-ai/repo/.env`，然后执行 `cd /opt/airport-ai/repo && docker compose up -d backend` 使其生效。

## 5. 离线/内网 CentOS 7 服务器更新（可选，免源码编译）

若目标 CentOS 7 测试服务器处于内网隔离环境、无法连接外网拉取 Maven/npm 依赖，可在**能联网的机器**上完成镜像构建并导出离线镜像包，再上传至内网 CentOS 7 服务器一键更新：

1. **在联网构建机上构建新版本并导出离线镜像包**：
   ```bash
   cd /opt/airport-ai/repo
   sudo bash scripts/docker-deploy.sh \
     --server-ip <测试服务器IP> \
     --export-images ./airport-ai-images.tar.gz
   ```
2. **将 `airport-ai-images.tar.gz`（以及新源码包 `airport-ai-src.tar.gz`，如有编排/脚本变更）上传至内网 CentOS 7 服务器 `/tmp/`**。
3. **在内网 CentOS 7 服务器上一键备份并加载新镜像启动**：
   ```bash
   sudo bash /opt/airport-ai/repo/scripts/docker-update.sh \
     --load-images /tmp/airport-ai-images.tar.gz
   ```

## 6. 更新后验收检查清单

更新脚本执行完毕后，请依次完成以下核查：

### 6.1 容器健康与 Flyway 迁移核查

```bash
cd /opt/airport-ai/repo

# 1. 查看所有容器状态（4 个容器均应为 Up / healthy）
docker compose ps

# 2. 检查后端健康接口（应返回 {"status":"UP"}）
curl -s http://127.0.0.1:8080/actuator/health

# 3. 检查前端 Nginx 入口可达（应返回 HTTP/1.1 200 OK）
curl -I http://127.0.0.1/

# 4. 检查后端启动日志中的 Flyway 数据库迁移与启动完成记录（确认无报错）
docker compose logs --tail=120 backend | grep -iE "flyway|migrated|started"
```

### 6.2 演示数据集与仿真设备同步（按需执行）

- **何时需要执行“演示数据重置”**：
  如果本次版本更新修改了 `DemoDataset.java`（如预置设备坐标、默认模板参数、标准场景初始位置等），数据库中已有的存量演示数据不会自动覆盖。此时需使用管理员账号 `admin` 登录前端（`http://<服务器IP>/`）：
  1. 进入 **演示数据重置** 页面。
  2. 输入确认短语 `恢复F2标准演示数据` 执行重置，将预置数据刷新为最新代码基线。
- **检查仿真设备在线状态**：
  进入 **设备管理** 或 **态势感知** 页面，确认 6 台标准 F2 仿真设备（`SIM_F2_DISPLAY`、`SIM_F2_BAGGAGE`、`SIM_F2_FLIGHT`、`SIM_F2_ROBOT`、`SIM_F2_LIGHT`、`SIM_F2_BROADCAST`）状态为 `ONLINE / READY`。由于后端容器重建后其内部托管的仿真子进程会重新初始化，如显示离线，可在平台 **设备管理 / 仿真控制** 界面重新拉起。

## 7. 异常回滚预案

若新版本上线后发现严重问题需立即回退至更新前的状态：

### 方式 1：使用 `docker-update.sh` 一键回滚（推荐）

```bash
# 1. 查看可回滚的历史备份时间戳列表
sudo bash /opt/airport-ai/repo/scripts/docker-update.sh --list-backups

# 2. 一键回滚到指定时间戳（自动恢复代码、还原数据库备份并切回备份镜像启动）
sudo bash /opt/airport-ai/repo/scripts/docker-update.sh --rollback <TIMESTAMP>

# （可选）若本次更新未涉及数据库表结构变更，不想覆盖数据库最新数据，可加 --skip-db-restore：
# sudo bash /opt/airport-ai/repo/scripts/docker-update.sh --rollback <TIMESTAMP> --skip-db-restore
```

### 方式 2：手动分步回滚命令（备查）

```bash
# 1. 恢复更新前的代码目录（保留 .env）
cd /opt/airport-ai
find /opt/airport-ai/repo -mindepth 1 -maxdepth 1 ! -name '.env' -exec rm -rf {} +
cp -a "/opt/airport-ai/backup/repo_<TS>/." /opt/airport-ai/repo/

# 2. 若新版本执行过新增的 Flyway 数据库迁移，需先停后端并还原数据库备份
cd /opt/airport-ai/repo
set -a && source .env && set +a
docker compose stop backend
docker compose exec -T postgres pg_restore --clean --if-exists -U "$DB_USERNAME" -d "$DB_NAME" \
  < "/opt/airport-ai/backup/db_<TS>.dump"

# 3. 重新构建并启动旧版本容器
sudo bash scripts/docker-deploy.sh --server-ip <服务器IP>
```
