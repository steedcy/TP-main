# 三类场景演示脚本执行手册

适用主线版本：`main`（`ecd67fc` 及以上，已包含 `PI-001`～`PI-005` 与 `AC-020`/`AC-021`/`AC-023` 实测验证）。  
建议演示总时长：**10～15 分钟**。

---

## 一、演前准备与环境就绪检查（演示前 5 分钟）

### 1. 服务与进程检查
1. 确认本机运行服务均处于正常状态：
   - 后端服务：`http://127.0.0.1:8080/actuator/health` 返回 `{"status":"UP"}`
   - 前端界面：`http://127.0.0.1:5173` 可正常访问
   - 7 台仿真设备进程：`8091～8097` 均已启动
2. 如刚重启过数据库或重置过演示数据，先执行一次幂等就绪脚本对齐设备能力与基线模板：
   ```powershell
   python -B scripts/repair-demo-readiness.py
   ```

### 2. 数据复位（可选）与账号登录
1. 若此前执行过大量测试，可先使用 **系统管理员** 账号（账号凭据见本机 `user.md`）登录管理后台，进入 **系统管理 → 标准演示数据集复位**（`/demo-data-reset`）确认演示基线干净。
2. 退出系统管理员账号，使用 **运行操作员** 账号（见本机 `user.md`）重新登录管理后台。

### 3. 演前面板核对
1. 打开 **运行总览** 页面，确认：
   - **在线代理**：`7`
   - **进行中任务**：`0`
2. 进入 **仿真控制** 页面（`/simulator`），核对下方仿真设备列表的 7 台设备全部满足：
   - **设备状态**：`在线`、`空闲`
   - **执行场景**：`正常成功`（若某台为 `设备错误`/`执行超时` 等，点击切换回 `正常成功`）
   - 7 台设备清单：`SIM_F2_FLIGHT`（航延屏 ×1）、`SIM_F2_DISPLAY` / `SIM_F2_DISPLAY_B`（智慧航显 ×2）、`SIM_F2_BAGGAGE` / `SIM_F2_BAGGAGE_B`（行李测量设备 ×2）、`SIM_F2_ROBOT` / `SIM_F2_ROBOT_B`（移动服务机器人 ×2）。
3. 建议在浏览器另开一个标签页停留在 **二维态势**（`/situation`），演示过程中可随时切过去展示机器人位置移动与实时指针坐标（`1260 × 6895` 底图）。

## 二、场景一：航班变更与旅客引导（约 3 分钟）

**对应需求**：`SRS_F026`（航班变更应对场景）  
**演示要点**：开放式任务提交 → 越权能力自动拦截与基线降级 → 三渠道协同发布（航延屏 + 智慧航显 + 移动机器人）与内容一致性闭环。

### 1. 操作步骤
1. 在 **仿真控制** 页面顶部 **【端到端演示任务】** 区域，找到第 1 张卡片 **【航班变更与旅客引导】**。
   - 卡片内置提交参数（无需手动填写）：
     - **任务族**：`FLIGHT_CHANGE_RESPONSE`
     - **航班号**：`CA1234`
     - **变更类型**：`DELAY`（延误）
     - **原计划时间**：当前日期 `22:30:00`
     - **变更后时间**：当前日期 `23:00:00`
     - **登机口**：`GATE_A05`
     - **变更说明**：`虚构航班CA1234延误30分钟，登机口GATE_A05不变`
     - **任务目标**：`虚构航班CA1234原计划22:30，延误30分钟至23:00，请通过航延屏发布变更、智慧航显发布提示，并由机器人引导旅客前往GATE_A05。`
2. 点击卡片上的 **【提交演示任务】** 按钮，等待右上角提示“已提交演示任务：TASK-YYYYMMDD-XXXX”。
3. 跳转至 **任务管理 → 任务列表**，点击该任务右侧的 **【详情】** 进入任务详情页（或点击刷新观察状态流转直至 `已完成`）。

### 2. 预期结果与讲解核验点
1. **规划校验与安全降级**：在 **计划版本 / 事件时间线** 中展示，若自主规划尝试使用任务定义未允许的能力（如 `CAP_ESCORT`），系统会以 `ERR_CAPABILITY_NOT_IN_TASK_DEFINITION` 拦截并自动切换至合规基线模板。
2. **三渠道指令内容一致**：在 **步骤分配 / 执行记录** 中核对 4 个步骤均成功完成，且前 3 个信息发布渠道内容均与输入一致（包含 `DELAY`、`23:00`、`GATE_A05`）：
   - 步骤 1：**航延屏**（`CAP_FLIGHT_UPDATE`）发布成功
   - 步骤 2：**智慧航显**（`CAP_INFO_DISPLAY`）展示引导成功
   - 步骤 3：**移动机器人**（`CAP_NOTIFICATION`）现场通知成功
   - 步骤 4：**移动机器人**（`CAP_NAVIGATION`）引导抵达 `GATE_A05`（回报 `ARRIVED`）
3. **渠道响应汇总**：详情页 **“航班变更渠道响应”** 卡片显示三渠道均为 `SUCCESS` 及各自响应耗时。

### 3. （可选扩展演练）条件必填与补充澄清
如需现场加演“缺信息追问补充”（对应 `TC-080` / `AC-021`），可在 **任务管理 → 提交任务**（`/tasks`）选择 `应急处置 / 航班变动应急协同`：
- 仅填基础信息但故意留空 **变更后时间**（`DELAY` 场景）：提交后任务停在 `待规划（PLANNING）`，0 计划版本，系统精准追问 `请补充变更后的航班时间`。
- 点击列表或详情中的 **【补充信息】**，在回答框填入 `2026-11-16T23:00:00`（或 `23:00`）并提交，任务立即恢复规划并执行至 `已完成`。

## 三、场景二：超规行李处置（约 4 分钟，分正常与超规双分支）

**对应需求**：`SRS_F024`（超规行李处置场景）  
**演示要点**：实测数据与标准阈值比对（三边和 `158 cm` / 重量 `32 kg`）→ 正常行李自动收敛结束 vs 超规测量事件触发多渠道告警与专柜引导（且不重复二次测量）。

### 阶段 A：正常行李分支（卡片入口）
1. 返回 **仿真控制** 页面，在 **【端到端演示任务】** 区域找到第 2 张卡片 **【超规行李处置】**。
   - 卡片内置提交参数（无需手动填写）：
     - **任务族**：`OVERSIZE_BAGGAGE_HANDLING`
     - **行李位置**：`T2值机岛A03`
     - **目标专柜**：`超规行李专柜B01`
     - **任务目标**：`请测量T2值机岛A03当前行李的长宽高和重量；超规时上报告警、由智慧航显发布超规行李专柜B01办理提示，并由移动机器人提供导航；正常行李留存测量结果后结束。`
2. 点击 **【提交演示任务】**，记录任务编号并进入 **任务管理 → 任务详情**。
3. **预期结果与核验点**：
   - 行李测量设备（`CAP_BAGGAGE_MEASURE`）实测返回 `55 × 40 × 20 cm`（三边和 `115 cm ≤ 158 cm`）、重量 `10 kg ≤ 32 kg`。
   - 系统记录事件 `BAGGAGE_WITHIN_LIMIT`，**仅下发并执行测量 1 步即自动置为 `已完成`**，不误触发超规告警与机器人导航，详情页不展示超规缴费提示。

### 阶段 B：超规行李分支（测量事件入口）
1. 返回 **仿真控制** 页面，向下滚动到 **【模拟行李测量事件触发（SRS_F024 / NT-S3-004）】** 卡片。
2. 点击 **【填入超规示例】** 按钮，核对表单自动填入的字段信息：
   - **行李位置**：`T2值机岛A03`
   - **长 (cm)**：`100`
   - **宽 (cm)**：`60`
   - **高 (cm)**：`40`（三边和 `200 cm > 158 cm`）
   - **重量 (kg)**：`28`
   - **目标柜台（可选）**：`超规行李专柜B01`
   - *（后台自动附带阈值参数：`dimensionThresholdCm = 158`、`weightThresholdKg = 32`、`thresholdSource = 附录F-五类设备能力边界清单 2.2 智能行李测量设备能力约束`）*
3. 点击 **【触发测量事件】** 按钮。
4. 卡片下方出现 **“最新触发结果: 超规行李”** 及任务链接，点击 **【查看任务详情 (ID: XXX)】** 进入详情页。
5. **预期结果与核验点**：
   - 系统直接复用测量事件样本（事件记录 `MEASUREMENT_EVENT_REUSED`），**不重复发起二次测量**。
   - 自动完成多渠道协同处置：**超规告警上报**（`CAP_OVERSIZE_ALERT`）+ **智慧航显发布专柜提示**（`CAP_INFO_DISPLAY`）+ **移动机器人现场通知与引导至 `超规行李专柜B01`**（`CAP_NOTIFICATION` / `CAP_NAVIGATION`，回报到达 `超规行李专柜B01`），任务状态 `已完成`（总步数 ≤ 5 步）。

## 四、场景三：特殊旅客陪同（约 3 分钟）

**对应需求**：`SRS_F025`（特殊旅客服务场景）  
**演示要点**：高风险业务识别（`RULE_ESCORT_SPECIAL_PASSENGER`）与基线自动降级 → 航显会合提示带起终点 → 同一台机器人先抵达会合点再陪同至登机口。

### 1. 操作步骤
1. 返回 **仿真控制** 页面，在 **【端到端演示任务】** 区域找到第 3 张卡片 **【特殊旅客陪同】**。
   - 卡片内置提交参数（无需手动填写）：
     - **任务族**：`SPECIAL_PASSENGER_SERVICE`
     - **协助类型**：`轮椅陪同`
     - **起点**：`T2值机区`
     - **目的地**：`GATE_A05`
     - **任务目标**：`请为虚构轮椅旅客在T2值机区通过智慧航显显示会合提示、通知现场人员，并安排服务机器人前往会合后陪同旅客前往GATE_A05。`
2. 点击 **【提交演示任务】**，记录任务编号并进入 **任务管理 → 任务详情**。

### 2. 预期结果与核验点
1. **高风险判定与基线降级**：在 **计划版本 / 事件时间线** 中指出，自主计划命中确定性高风险规则 `RULE_ESCORT_SPECIAL_PASSENGER`，监督智能体判定为 `HIGH` 风险并自动切换至标准基线模板执行。
2. **多渠道会合与同一机器人陪同闭环**：核对 4 个步骤均成功完成：
   - 步骤 1：**智慧航显**（`CAP_INFO_DISPLAY`）发布会合提示，内容同时包含会合地点 `T2值机区` 与目的地 `GATE_A05`。
   - 步骤 2：**移动机器人**（`CAP_NOTIFICATION`）通知现场人员（含起点与终点）。
   - 步骤 3：**移动机器人**（`CAP_NAVIGATION`）前往会合点 `T2值机区`，返回 `arrivalLocation = T2值机区`、`arrivalStatus = ARRIVED`。
   - 步骤 4：**同一台移动机器人**（`CAP_ESCORT`）从起点陪同旅客前往 `GATE_A05`，返回 `ARRIVED`，任务置为 `已完成`。
3. **协同服务卡片与隐私合规**：详情页 **“特殊旅客协助与陪同协同服务”** 卡片正常渲染协助类型（`轮椅陪同`）、起点（`T2值机区`）、目的地（`GATE_A05`）及完成状态，全流程不收集旅客真实姓名/证件号/手机号。

### 3. （可选扩展演练）缺项追问补充与隐私脱敏
如需现场加演缺项补充（对应 `TC-077` / `AC-020`），可通过接口或任务提交页提交缺少任一字段的特殊旅客任务并补充：

| 故意缺失字段 | 系统追问提示 | 补充表单填入值 | 补齐后预期 |
| :--- | :--- | :--- | :--- |
| 缺 **协助类型** | `请补充协助类型（如轮椅、视障或听障陪同）` | `轮椅陪同` | 0 计划拦截 → 补齐后 `已完成` |
| 缺 **起点** | `请补充服务起点` | `T2值机区` | 0 计划拦截 → 补齐后 `已完成` |
| 缺 **目的地** | `请补充服务目的地` | `GATE_A05` | 0 计划拦截 → 补齐后 `已完成` |

## 五、演示收口与演后复位（约 2 分钟）

1. **过程追溯与二维态势联动**：
   - 在最后一个任务的详情页，点击关联 **过程追溯 / 事件时间线**，向观众展示从 `NORMAL_GOAL_SUBMITTED`、监督降级、设备命令下发到 `COMPLETED` 的完整可追溯链。
   - 切换至 **二维态势** 标签页，展示设备位置更新与在线空闲状态。
   - 如需展示审计能力，可切换 **系统管理员** 登录 **操作记录**，核对本轮任务提交的审计记录。
2. **演后环境恢复**：
   - 返回 **仿真控制** 页面，确认 7 台设备均已自动释放占用，状态恢复为 **在线 / 空闲**，执行场景均为 **正常成功**。
   - 如演示中执行过停用设备或故障注入演练，务必恢复对应设备在线并终止未结案的演示任务，使 **运行总览** 恢复“在线代理 = 7、进行中任务 = 0”。
