# 任务目标提交输入规范

**适用接口**: `POST /api/v1/tasks`  
**适用角色**: `OPERATOR`（运行操作员）  
**关联源码**: `TaskController.java`、`SubmitTaskRequest.java`、`TaskService.java`、`SceneParamsPrivacyGuard.java`、`SceneParamsValidator.java`、`RequiredInfoGuard.java`

---

## 1. 调用前提与权限要求

1. **账号角色**：仅 **`OPERATOR`（运行操作员）** 角色可提交正式任务目标（`SYSTEM_ADMIN` 与 `CONFIG_ADMIN` 不可提交）。
2. **设备代理在线**：系统中必须至少存在 **1 个状态为 `ENABLED` 且 `ONLINE` 的设备代理**，否则提交会直接被拦截（返回 `NO_AVAILABLE_DEVICE_AGENT`）。

---

## 2. 请求体字段规范（JSON）

| 字段名 | 是否必填 | 类型 | 长度与格式约束 | 说明 |
|---|---|---|---|---|
| `taskGoal` | **必填** | `String` | 不可为空白；长度 **1 ~ 500 字符** | 自然语言任务目标描述。 |
| `taskFamily` | 可选 | `String` | 必须为系统中**已启用**的任务定义编码 | 留空时由目标理解模型自动推断任务族；若填写但不存在或已停用，直接拒绝提交。 |
| `sceneParams` | 可选 | `Object` (`Map<String, Object>`) | 合法 JSON 对象，禁止包含隐私字段 | 结构化场景参数键值对，用于辅助目标理解与模板参数绑定。 |

### 预置任务族编码（`taskFamily`）

| 任务族编码 | 名称 |
|---|---|
| `OVERSIZE_BAGGAGE_HANDLING` | 超规行李处置 |
| `SPECIAL_PASSENGER_SERVICE` | 特殊旅客服务 |
| `FLIGHT_CHANGE_RESPONSE` | 航班变更应对 |

> 若配置管理员新增了自定义任务定义并启用，也可直接传入对应自定义编码。

---

## 3. `sceneParams` 校验规则

### 3.1 隐私与脱敏拦截（一票否决）

系统会递归扫描 `sceneParams` 的所有层级（对象键名、数组元素及文本内容），**严禁出现旅客真实身份信息**。命中以下任意一项即直接拒绝提交（不建任务、不持久化、不送模型）：

- **敏感字段名**（忽略大小写及 `_`、`-`、`.` 分隔符）：
  - 英文：`passengerName`、`passengerId`、`passenger`、`idCard`、`idNumber`、`identityDocument`、`passport`、`passportNumber`、`certificateNo`、`phone`、`mobile`、`tel`、`telephone`、`email`、`realName`、`fullName` 等。
  - 中文：`旅客姓名`、`乘客姓名`、`姓名`、`真实姓名`、`身份证`、`身份证号`、`证件号`、`护照`、`护照号`、`手机号`、`手机`、`电话`、`联系电话`、`邮箱`、`电子邮箱`、`旅客`、`乘客`、`身份` 等。
- **敏感文本格式**：
  - 18 位中国居民身份证号
  - 11 位中国大陆手机号
  - 电子邮箱地址
  - 带有上述敏感键名模式的键值对文本（如 `姓名: 张三`、`电话=13800138000`）

### 3.2 预置三类任务族的必要信息要求

对于预置任务族，若提交时缺少以下必要信息，系统允许建单但会在目标理解阶段进入**追问澄清**状态；若已在 `sceneParams`（或 `taskGoal` 解析结果）中提供，则直接进入规划阶段：

| 任务族 | 必要信息 | 对应 `sceneParams` 可识别键名 | 备注 |
|---|---|---|---|
| `OVERSIZE_BAGGAGE_HANDLING` | 行李所在位置 | `baggageLocation` | `targetCounter`、`baggageId` 可选，未填时系统自动补默认值 |
| `SPECIAL_PASSENGER_SERVICE` | 协助类型 | `assistanceType` | 如 `轮椅陪同`、`视障陪同`、`听障陪同` |
| `SPECIAL_PASSENGER_SERVICE` | 服务起点 | `origin` / `startLocation` / `originLocation` | 也可在 `taskGoal` 中明确写出以便目标理解提取 |
| `SPECIAL_PASSENGER_SERVICE` | 服务目的地 | `destination` / `targetLocation` / `targetPlace` | 也可在 `taskGoal` 中明确写出以便目标理解提取 |
| `FLIGHT_CHANGE_RESPONSE` | 航班号 | `flightNumber` | 如 `CA1234`、`TEST1022` |
| `FLIGHT_CHANGE_RESPONSE` | 变更内容 | `changeType` / `changeDescription` / `updateType` / `updateContent` | 如 `GATE_CHANGE`、`DELAY` 或具体变更描述 |

### 3.3 自定义扩展任务族的强校验规则

对于非预置的自定义任务定义，系统在**提交建单前**即按该任务定义声明的 `sceneParams` 规则进行强校验，不通过则直接拒绝：

- **必填校验**：所有声明为 `required = true` 的参数必须提供且不可为空白。
- **类型校验**：
  - `String`：必须为字符串，且长度 **≤ 500 字符**
  - `Integer`：必须为整数数值
  - `Double`：必须为数字类型
  - `Boolean`：必须为布尔值或 `"true"` / `"false"`
- 未声明的额外附加字段不会触发拒绝。

## 4. 标准提交示例

### 示例 1：超规行李处置（`OVERSIZE_BAGGAGE_HANDLING`）

```json
{
  "taskGoal": "对F2_BAGGAGE_POINT的超规行李进行测量告警，并在航显播报后引导前往F2_SERVICE_POINT",
  "taskFamily": "OVERSIZE_BAGGAGE_HANDLING",
  "sceneParams": {
    "baggageLocation": "F2_BAGGAGE_POINT",
    "targetCounter": "F2_SERVICE_POINT"
  }
}
```

### 示例 2：特殊旅客服务（`SPECIAL_PASSENGER_SERVICE`）

```json
{
  "taskGoal": "安排机器人协助轮椅旅客从F2_SERVICE_POINT前往F2_TEST_GATE登机，并同步航显和现场通知",
  "taskFamily": "SPECIAL_PASSENGER_SERVICE",
  "sceneParams": {
    "assistanceType": "轮椅陪同",
    "origin": "F2_SERVICE_POINT",
    "destination": "F2_TEST_GATE"
  }
}
```

### 示例 3：航班变更应对（`FLIGHT_CHANGE_RESPONSE`）

```json
{
  "taskGoal": "航班TEST1022登机口变更至F2_TEST_GATE，请通过航显屏发布变更信息并安排引导",
  "taskFamily": "FLIGHT_CHANGE_RESPONSE",
  "sceneParams": {
    "flightNumber": "TEST1022",
    "updateType": "GATE_CHANGE",
    "updateContent": "航班TEST1022登机口变更为F2_TEST_GATE"
  }
}
```

### 示例 4：开放式任务目标（不指定 `taskFamily`）

```json
{
  "taskGoal": "请协助将位于F2_BAGGAGE_POINT的超规行李引导至F2_SERVICE_POINT办理托运",
  "sceneParams": {
    "baggageLocation": "F2_BAGGAGE_POINT"
  }
}
```
