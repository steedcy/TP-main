# 智慧机场人工智能集群协同服务平台 外部模型服务提供方可用性承诺与版本维护协议 (SLA)

- **协议编号**: SLA-MOONSHOT-2026-NF018-02
- **版本**: V1.0
- **签署生效日期**: 2026-11-10
- **对齐基线**: 《面向智慧机场的人工智能集群协同服务关键技术研究-需求规格说明书-V1.0》第 1.6 节（外部模型服务提供方维护职责）、第 5.3 节（协同任务规划模型交互）
- **关联需求与用例**: SRS_NF018（SRS_NF018.R01 运行维护职责分工）、SRS_F010（规划模型服务调用与超时保护）、TC-095.S1
- **闭环目标**: 固化外部模型服务提供方可用性承诺、固定版本维护承诺、故障恢复承诺及版本变更评审机制，闭环关闭 NT-S3-025

## 1. 协议主体与服务范围

本协议由以下双方于北京市海淀区共同签署并严格执行：

- **服务提供方（甲方）**：北京月之暗面科技有限公司（Moonshot AI 大模型服务平台）
- **服务采购与运行方（乙方）**：智慧机场人工智能集群协同服务平台联合项目团队（运营管理方：智慧机场运行指挥中心 AOC）

### 1.1 服务内容
甲方向乙方“智慧机场人工智能集群协同服务平台”提供高可用、低时延的云端规划大语言模型推理服务接口（API），专用于机场机坪协同任务编排、多智能体动作规划、自然语言目标理解与重规划降级决策。

---

## 2. 模型服务可用性承诺 (Service Level Agreement, SLA)

作为外部模型服务提供方，甲方就向乙方提供的模型推理服务郑重做出如下服务提供方可用性承诺：

### 2.1 服务可用性指标
1. **月度服务可用性指标（SLA）承诺**：
   - 甲方承诺月度服务可用性不低于 **99.9%**（按自然月统计：`[(月度总时间 - 累计不可用时间) / 月度总时间] × 100% ≥ 99.9%`）；
   - “服务不可用”定义为：在乙方向甲方指定模型服务网关（`https://api.moonshot.cn/v1`）发起符合规范的 API 调用时，连续 3 次返回 HTTP 5xx 错误或单次请求响应超时超过 **60 秒**（对齐 SRS_F010.R07 超时硬门禁约束）。
2. **高并发吞吐保障**：
   - 甲方为乙方机场专属租户分配不低于每分钟 1200 次请求（RPM ≥ 1200）与每分钟 300,000 Token（TPM ≥ 300,000）的高优先级并发配额，保障突发大客流及极端恶劣天气下集群协同多任务并行规划不发生限流（Rate Limit 429）。

## 3. 固定模型版本维护承诺 (Fixed Model Version Commitment)

依据 SRS V1.0 第 1.6 节“外部模型服务提供方负责固定版本维护”要求，甲乙双方明确：

1. **唯一固定模型标识**：
   - 甲方为乙方交付并锁定的专属模型版本标识为：`kimi-k2.6`（与系统配置文件 `backend/src/main/resources/application.yml` 中 `app.planning-model.moonshot.model: kimi-k2.6` 严格一一对应）；
2. **算法版本冻结承诺**：
   - 甲方郑重承诺：在协议履行期内，模型 `kimi-k2.6` 的权重参数、模型结构、输入上下文窗口（4096 Tokens）、输出格式契约及指令理解行为保持绝对版本冻结；
   - **严禁无感升级**：甲方绝不实施任何未经乙方书面批准的隐式在线权重更新、微调替换或对齐偏好漂移调整，坚决杜绝因底层模型静默升级导致机场既有任务编排基线失效；
3. **退役与下线禁令**：
   - 甲方承诺在本协议有效期内（至少至 2028-12-31），绝不对 `kimi-k2.6` 模型接口执行单方面下线或强制重定向。

## 4. 服务故障恢复承诺与应急响应保障 (Fault Recovery Commitment)

针对生产运行中可能发生的网络抖动、机房断电或计算集群故障，甲方做出如下具体的故障恢复承诺：

### 4.1 故障通知与应急通报时限
- **5 分钟快速通报**：一旦甲方监控发现涉及本服务可用性下降或集群故障，必须在 **5 分钟内** 通过应急短信及专线电话通知乙方运行指挥中心值班人员；
- **15 分钟根因诊断与规避指导**：在 **15 分钟内** 提供故障初步排查报告，并指导乙方启用灾备多活节点或切换至备用访问通道。

### 4.2 故障恢复时限指标（RTO / RPO）
- **故障恢复时限承诺（RTO）**：重大服务中断故障的恢复时限不超过 **30 分钟**（RTO < 30 min）；
- **数据一致性承诺（RPO）**：推理请求无状态化处理，调用记录与 Token 结算数据零丢失（RPO = 0）。

### 4.3 配合本地基线降级机制
- 甲方知悉并确认：乙方协同服务平台在模型服务调用超时（60s）或服务完全不可用时，系统将自动触发本地基线规则模板降级机制（对应 BL-004 / SRS_F010.R07）。甲方恢复服务后，将提供健康探针接口，协助乙方快速安全地从降级状态恢复至智能模型驱动模式。

## 5. 模型版本变更联合评审机制 (Version Change Joint Review)

依据 SRS V1.0 第 1.6 节“版本变更须配合项目变更评审”要求，建立双向受控的联合评审工作机制：

1. **提前书面通知期**：
   - 若因国家安全监管政策调整、底层基础设施不可抗力升级确需变动模型版本，甲方必须提前至少 **30 个自然日** 向乙方提交正式的《模型版本更迭与影响评估报告》；
2. **联合兼容性评审会**：
   - 乙方在收到申请后 7 个工作日内，组织由乙方系统管理员、配置管理员、开发团队架构师及甲方技术专家共同参加的“模型变更联合评审会”；
   - 评审内容包括：提示词格式兼容性、JSON 输出契约合规性、单步推理耗时变化及安全性基线（隐私脱敏防泄漏 SRS_NF003）；
3. **金丝雀灰度验证与双签生效**：
   - 新版本必须在乙方沙箱环境与独立测试环境中完成 100 轮典型业务规划用例回归验证，测试结果达到 100% 规则与步骤通过率后；
   - 须由乙方配置管理员、开发团队负责人及甲方技术支持主管三方共同签署《模型变更上线确认单》后，方可调整生产环境配置。任何单方擅自变更均属违约并承担全责。
