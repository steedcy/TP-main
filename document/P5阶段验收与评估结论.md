# P5阶段验收与评估结论

- 阶段：P5 需求差距收口
- 复核日期：2026-10-14
- 对照基线：SRS V1.4（F001–F028、8.2、NF001–NF015）、附录E V2.0、附录B V2.0、附录F V1.0
- 结论：**P5本地可执行交付通过；系统整体验收未完成，须在依赖就绪后复验。**

## 1. 交付范围与结论

本阶段复核P1—P4源码和阶段记录，更新F001—F028映射及验收证据，复核权限、操作审计、错误响应和敏感信息边界，修订部署手册中与Flyway、Spring Boot配置、Java启动参数、Nginx API路径及仿真进程托管不一致之处，并执行当前环境可运行的后端/仿真器测试、前端生产构建和部署工具语法/编译检查。

P5完成标准是“现有可执行项有真实证据，未具备环境的验收项有准确状态及复现步骤”，不是把所有SRS需求判为通过。F001—F028的逐条状态、实现位置和附录E映射见[`P5需求差距收口与验收矩阵.md`](./P5需求差距收口与验收矩阵.md)。

## 3. 对照SRS 8.2及附录E的评价

- **任务状态与监督降级（8.2.1）**：组件和仿真器覆盖不能证明任务全局状态迁移、模型不可用降级及待人工路径整体验收；须在应用数据库、规划和监督服务就绪后执行附录E规划/执行用例。
- **五步限制（8.2.2）及局部重新规划（8.2.3）**：代码中存在步骤和次数限制，但本轮未进行数据库支持的完整任务规划/执行、版本保留和多分支验收，保持待验收。
- **运动安全边界（8.2.4）**：运行时/协议已有运动控制字段拦截实现和自动化覆盖；最终仍需按INT_001对平台入口、代理网关和设备侧做集成复验。
- **规划模型服务（8.2.5）**：未配置外部模型，未执行真实成功、60秒超时、错误结构和降级验收。
- **附录E安全、权限、审计**：服务端角色注解与方法级权限保护、设备独立Bearer认证、越权审计和异常脱敏已有源码/单测证据；Redis会话生命周期、三种用户角色的全接口权限矩阵、数据库操作记录落库及全平台敏感字段抽查仍未整体验收。
- **附录E集成、容量与稳定性**：未执行需要PostgreSQL/Redis/规划服务的INT_002—005、007—008全链路；未执行10并发任务/用户、20设备心跳、JMeter指标、8小时稳定性、重启恢复、备份恢复及目标浏览器验收。

WebSocket不是当前版本的验收目标；系统以`GET /api/v1/situation/snapshot`及5秒前端轮询为准。当前判定依照附录B的轮询路径，不把Nginx预留WebSocket反向代理配置当作服务端功能。

## 4. 外部依赖与后续复现步骤

以下项目因本轮未连接或未配置依赖而不能给出通过结论：

1. **PostgreSQL / Flyway**：本机5432端口可达，但应用使用仓库默认账号尝试启动时认证失败（SQLSTATE 28P01），未运行迁移。部署方需提供有效数据库账号。按[`部署实施手册.md`](./部署实施手册.md)创建空库并授予迁移权限；通过`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`注入配置后启动后端。核对`flyway_schema_history`已应用V1—V13，验证设备凭据、命令/报告幂等表和任务事务，再执行附录E数据库集成用例。不要在报告中存放密码。
2. **Redis会话**：本机6379端口可达，无认证PING返回PONG；尚未进行平台会话集成验证。配置`REDIS_HOST`、`REDIS_PORT`和所需的`REDIS_PASSWORD`，待后端可启动后分别验证登录、30分钟空闲过期/重新认证、锁定账号及三角色授权矩阵，并检查越权操作记录持久化。
3. **规划/监督服务**：配置`PLANNING_MODEL_ENDPOINT`、`PLANNING_MODEL_API_KEY`及监督服务地址/凭据后，执行成功、不可用、超时、错误结构、高风险基线匹配失败转人工和计划版本追溯用例；覆盖INT_002、INT_005及相关规划执行验收。
4. **性能与稳定性**：使用附录C/E指定目标规模与数据集运行压测，保存原始JMeter结果、系统资源采样及阈值比较；执行至少8小时运行、进程重启和备份恢复并保留时间戳日志。
5. **现场/浏览器验收**：在目标环境按三个演示入口验证前端刷新、角色范围和实际设备代理快照；跨目标浏览器执行页面及任务流程检查。

上述验收全部通过并归档证据后，才可把相关需求由“部分覆盖/待验收”更新为最终通过。
