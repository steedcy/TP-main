## 1. 测试策略

### 1.1 测试类型

| 测试类型 | 是否执行 | 测试范围 | 负责方 |
|---|---|---|---|
| 单元测试 | 是 | 三类校验、监督判定规则、能力边界校验等核心业务逻辑 | 开发团队 |
| 集成测试 | 是 | 内部模块接口调用、外部规划模型服务调用、数据库交互 | 开发团队 + 测试团队 |
| 功能测试 | 是 | 全部功能需求（第五章） | 测试团队 |
| 性能测试 | 是 | 按附录C性能指标详表执行 | 测试团队 |
| 安全测试 | 是 | 密码存储、会话管理、权限校验、运动安全字段拦截 | 测试团队 |
| 用户验收测试（UAT） | 是 | 核心业务场景（超规行李处置、特殊旅客服务、航班变更应对） | 客户 + 测试团队 |

### 1.2 测试流程

```
┌─────────────┐
│ 单元测试    │ ← 开发人员自测，覆盖率>70%
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 集成测试    │ ← 测试内部模块接口、外部规划模型服务调用
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 功能测试    │ ← 测试全部功能需求
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 回归测试    │ ← 确保新功能未破坏已有功能
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 用户验收测试│ ← 客户确认系统满足需求
└─────────────┘
```

## 2. 测试环境

### 2.1 测试环境配置

| 环境类型 | 配置 | 用途 |
|---|---|---|
| 开发环境 | 开发人员本地机器 | 单元测试、功能调试 |
| 测试环境 | 一套服务器或开发验证环境（同SRS_NF013部署规模） | 集成测试、功能测试、性能测试 |
| 演示环境 | 客户现场部署 | 用户验收测试、最终演示 |

### 2.2 测试数据

**测试数据准备**:
- **模拟用户数据**: 创建三类角色测试账号（系统管理员、运行操作员、配置管理员）
- **模拟设备数据**: 配置5类设备的仿真体（智慧航显、智能行李测量设备、航延屏、移动服务机器人）及仿真体本身，合计不超过10个（演示配置上限）
- **模拟任务数据**: 覆盖三类预置任务族（超规行李处置、特殊旅客服务、航班变更应对），旅客/航班信息均使用虚构或脱敏数据
- **模拟规划模型服务**: 使用模拟模型接口进行接口自测，不作为验收基线；验收基线以实际接入的模型服务为准

**测试数据隔离**:
- 测试环境与演示环境数据完全隔离
- 特殊旅客服务场景不得使用真实身份信息，测试数据须为虚构或脱敏数据

### 3.2 用户认证与账号管理模块（对应5.1.1，含密码锁定补充）

**TC_AUTH_001: 用户登录成功**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户账号已创建（username: admin, password: Admin@12345），状态为ACTIVE |
| 测试步骤 | 1. 打开登录页<br>2. 输入账号"admin"<br>3. 输入密码"Admin@12345"<br>4. 点击"登录"按钮 |
| 预期结果 | 1. 跳转到运行总览页<br>2. 右上角显示当前账号与角色名称<br>3. 返回有效Token |
| 通过标准 | 登录成功，写入登录成功操作记录 |

**TC_AUTH_002: 账号或密码错误**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户账号已创建，未被锁定 |
| 测试步骤 | 1. 输入账号"admin"<br>2. 输入错误密码"wrongpassword"<br>3. 点击"登录"按钮 |
| 预期结果 | 1. 统一提示"账号或密码错误"，不区分账号不存在/密码错误/账号停用<br>2. 不跳转页面，不建立会话 |
| 通过标准 | 显示统一错误提示，错误码2002，写入登录失败操作记录 |

**TC_AUTH_003: 会话空闲超时**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户已登录，会话空闲超过30分钟 |
| 测试步骤 | 1. 登录后保持页面不操作30分钟以上<br>2. 尝试执行任意需要认证的操作 |
| 预期结果 | 1. 跳转到登录页并提示重新登录<br>2. 重新登录后返回原页面 |
| 通过标准 | 会话空闲30分钟后失效检测正常（对应SRS_NF002），重新登录成功 |

**TC_AUTH_004: 连续3次密码错误锁定账号**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户账号zhangsan存在，状态ACTIVE，failed_login_attempts=0 |
| 测试步骤 | 1. 输入账号"zhangsan"，密码"wrong1"，点击登录<br>2. 再次输入密码"wrong2"，点击登录<br>3. 再次输入密码"wrong3"，点击登录 |
| 预期结果 | 第1、2次：统一提示"账号或密码错误"<br>第3次：统一提示"账号或密码错误"，后台状态变为LOCKED<br>数据库：status=LOCKED, failed_login_attempts=3, locked_at有值, locked_reason="连续3次密码输入错误" |
| 通过标准 | 前端提示始终统一（不透露剩余次数，与TC_AUTH_002一致的统一提示原则），账号状态正确变更为LOCKED |

**TC_AUTH_005: 被锁定账号无法登录**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户账号zhangsan已被锁定（status=LOCKED） |
| 测试步骤 | 1. 输入账号"zhangsan"，正确密码，点击登录 |
| 预期结果 | 1. 统一提示"账号或密码错误"<br>2. 返回错误码2005<br>3. 不建立会话 |
| 通过标准 | 锁定账号无法登录，且提示与其他登录失败场景一致，不额外暴露锁定状态 |

**TC_AUTH_006: 系统管理员解锁账号**

| 字段 | 内容 |
|---|---|
| 前置条件 | 1. 系统管理员已登录<br>2. 用户账号zhangsan已被锁定 |
| 测试步骤 | 1. 进入账号管理页面<br>2. 筛选状态为"已锁定"<br>3. 找到zhangsan，点击"解锁"按钮<br>4. 确认解锁操作 |
| 预期结果 | 1. 提示"用户zhangsan已解锁"<br>2. 数据库：status=ACTIVE, failed_login_attempts=0<br>3. 操作记录中写入解锁操作（操作人、时间、结果）<br>4. zhangsan可正常登录 |
| 通过标准 | 解锁成功，账号恢复正常，操作记录完整 |

**TC_AUTH_007: 登录成功后失败计数重置**

| 字段 | 内容 |
|---|---|
| 前置条件 | 用户账号zhangsan，failed_login_attempts=2，未锁定 |
| 测试步骤 | 1. 输入正确账号密码，点击登录 |
| 预期结果 | 1. 登录成功<br>2. 数据库：failed_login_attempts重置为0 |
| 通过标准 | 失败计数正确重置，避免历史失败次数累积到未来 |

**TC_AUTH_008: 非系统管理员无法解锁账号**

| 字段 | 内容 |
|---|---|
| 前置条件 | 1. 运行操作员已登录<br>2. 用户账号zhangsan已被锁定 |
| 测试步骤 | 1. 以运行操作员身份调用解锁接口`POST /api/v1/users/{userId}/unlock` |
| 预期结果 | 返回错误码2003"无权限访问"，账号未解锁，写入越权调用操作记录 |
| 通过标准 | 权限由服务端校验，非前端隐藏，越权请求被拒绝（对应SRS_NF004） |

**TC_AUTH_009: 停用账号拒绝登录**

| 字段 | 内容 |
|---|---|
| 前置条件 | 系统管理员已停用某账号（status=INACTIVE） |

| 通过标准 | 停用账号无法登录，且提示不区分停用与密码错误 |

**TC_AUTH_010: 密码不可逆存储**

| 字段 | 内容 |
|---|---|
| 前置条件 | 已创建测试账号 |
| 测试步骤 | 1. 查看数据库用户表中密码字段<br>2. 查看应用日志中登录相关记录 |

| 通过标准 | 全链路无密码原值泄露（对应SRS_NF001） |
