## 1. 部署概述

### 1.1 部署架构

**部署方式**: 单节点虚拟机（VM）部署，一套服务器或开发验证环境即可（对应SRS_NF013，不要求高可用集群与异地容灾）

**操作系统**: Ubuntu 22.04 LTS Server

**部署拓扑**:

```
┌─────────────────────────────────────────────────┐
│          Ubuntu 22.04 LTS Server VM             │
│                                                 │
│  ┌───────────────────────────────────────────┐ │
│  │  应用服务（Spring Boot单体应用）            │ │
│  │  - Airport AI App      :8080              │ │
│  └───────────────────────────────────────────┘ │
│                                                 │
│  ┌───────────────────────────────────────────┐ │
│  │  数据存储服务                              │ │
│  │  - PostgreSQL          :5432              │ │
│  │  - Redis               :6379              │ │
│  └───────────────────────────────────────────┘ │
│                                                 │
│  ┌───────────────────────────────────────────┐ │
│  │  前端服务                                  │ │
│  │  - Nginx (静态文件)     :80               │ │
│  └───────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
        │ HTTPS
        ▼
┌─────────────────────────────────────────────────┐
│  规划模型服务（外部，可替换，不在本机部署）        │
└─────────────────────────────────────────────────┘
```

### 1.2 硬件配置要求

对齐附录C第6.1节单机部署规模（≤10并发用户、≤20接入设备、≤10并发任务）：

| 资源 | 最低配置 | 推荐配置 |
|---|---|---|
| CPU | 4核 | 8核 |
| 内存 | 8GB | 16GB |
| 磁盘 | 100GB SSD | 200GB SSD |
| 网络 | 10Mbps | 30Mbps |

说明：本项目无视频流传输需求，硬件配置显著低于视频监控类项目，无需按10路视频流规模预留资源。

|---|---|---|

## 2. 环境准备

### 2.1 系统初始化

#### 2.1.1 更新系统软件包

```bash
sudo apt update
sudo apt upgrade -y
```

#### 2.1.2 安装基础工具

```bash
sudo apt install -y curl wget vim git unzip net-tools
```

#### 2.1.3 配置时区

```bash
sudo timedatectl set-timezone Asia/Shanghai
```

#### 2.1.4 配置防火墙（可选，内网环境可跳过）

```bash
# 安装ufw
sudo apt install -y ufw

# 允许SSH
sudo ufw allow 22/tcp

# 允许HTTP/HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 应用、PostgreSQL和Redis在单机部署时只绑定/接受本机流量，不开放8080/5432/6379公网入站端口。
# 只有确需跨主机访问时，才按下文的私网地址和应用服务器来源网段放行。

# 启用防火墙
sudo ufw enable
```

### 2.2 创建应用目录

```bash
# 创建应用根目录
sudo mkdir -p /opt/airport-ai

# 创建子目录
sudo mkdir -p /opt/airport-ai/app
sudo mkdir -p /etc/airport-ai
sudo mkdir -p /opt/airport-ai/logs
sudo mkdir -p /opt/airport-ai/frontend

# 设置权限（假设应用用户为airportai）
sudo useradd -r -s /bin/false airportai
sudo chown -R airportai:airportai /opt/airport-ai
```

## 3. 基础软件安装

### 3.1 安装JDK 17

```bash
# 安装OpenJDK 17
sudo apt install -y openjdk-17-jdk

# 验证安装
java -version

# 配置JAVA_HOME
echo 'export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64' | sudo tee -a /etc/profile
echo 'export PATH=$JAVA_HOME/bin:$PATH' | sudo tee -a /etc/profile
source /etc/profile
```

### 3.2 安装PostgreSQL 15

```bash
# 添加PostgreSQL官方仓库
sudo sh -c 'echo "deb http://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'
wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo apt-key add -

# 安装PostgreSQL 15
sudo apt update
sudo apt install -y postgresql-15 postgresql-contrib-15

# 启动服务
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 验证安装
sudo systemctl status postgresql
```

### 3.3 安装Redis 7.2

```bash
# 添加Redis官方仓库
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list

# 安装Redis
sudo apt update
sudo apt install -y redis

# 启动服务
sudo systemctl start redis-server
sudo systemctl enable redis-server

# 验证安装
redis-cli ping
# 输出: PONG
```

### 3.4 安装Nginx

```bash
# 安装Nginx
sudo apt install -y nginx

# 启动服务
sudo systemctl start nginx
sudo systemctl enable nginx

# 验证安装
sudo systemctl status nginx
# 访问: http://<服务器IP>
```

说明：本项目不引入InfluxDB、RabbitMQ、SeaweedFS等组件（对应附录A第3.3节技术栈选型），无需额外安装步骤。

## 4. 数据库初始化

### 4.1 PostgreSQL数据库初始化

#### 4.1.1 创建数据库和用户

```bash
# 切换到postgres用户
sudo -u postgres psql

# 在psql命令行中执行：
CREATE DATABASE airport_ai;
CREATE USER airportai_user WITH PASSWORD 'your_secure_password';
GRANT ALL PRIVILEGES ON DATABASE airport_ai TO airportai_user;
\c airport_ai
GRANT USAGE, CREATE ON SCHEMA public TO airportai_user;
\q
```

#### 4.1.2 由Flyway执行数据库迁移

应用启动时由Flyway按 V1 至 V13 自动迁移。不要手工执行旧版DDL或在Flyway之外修改受管表结构；部署报告应记录 `flyway_schema_history` 中已应用的版本。

#### 4.1.3 初始化账号与权限

V3 Flyway migration seeds the administrator row with a non-login placeholder hash and initializes roles/configuration. After the first application start applies Flyway, and before exposing the service through Nginx, install a real BCrypt password using the repository helper. The helper prompts twice without echo, updates only the known placeholder row, and never accepts the password as a command-line argument:

```bash
# Set DB_HOST/DB_PORT/DB_NAME/DB_USERNAME/DB_PASSWORD from the secret manager in this shell.
python3 scripts/bootstrap-admin.py
```

The script requires Python 3, JDK/Maven, `psql`, and a DB account allowed to update `users`. It prompts for the password without echoing it, uses the application BCrypt encoder, and updates only the initial placeholder row; the password is never passed on a command line. Set DB environment values before running. Do not apply legacy `init_data.sql` on top of a Flyway-managed schema. Verify successful login before public access.

#### 4.1.4 配置PostgreSQL远程访问（仅独立数据库主机需要）

```bash
# 编辑postgresql.conf
sudo vim /etc/postgresql/15/main/postgresql.conf
# 修改: listen_addresses = '<数据库私网IP>'

# 编辑pg_hba.conf
sudo vim /etc/postgresql/15/main/pg_hba.conf
# 添加仅允许应用服务器来源网段的规则，例如：
# host    airport_ai    airportai_user    <应用服务器私网CIDR>    scram-sha-256

# 重启PostgreSQL
sudo systemctl restart postgresql
```

### 4.2 Redis配置

```bash
# 编辑Redis配置文件
sudo vim /etc/redis/redis.conf

# 修改以下配置：
# bind 127.0.0.1          # 单机默认仅监听本机；远程时绑定私网IP，并配合来源网段防火墙规则
# requirepass your_redis_password  # 设置密码
# maxmemory 1gb           # 最大内存限制（对齐附录C第3.2节存储容量规划）
# maxmemory-policy allkeys-lru  # 内存淘汰策略

# 重启Redis
sudo systemctl restart redis-server
```

## 5. 应用服务部署

### 5.1 上传应用JAR包

```bash
# 上传应用JAR包到服务器（单体应用，仅一个JAR包）
scp airport-ai-app-1.0.0.jar user@<服务器IP>:/opt/airport-ai/app/

# 设置权限
sudo chown -R airportai:airportai /opt/airport-ai/app/
```

### 5.2 配置应用环境

#### 5.2.1 Spring Boot环境配置

项目配置键和默认值以`backend/src/main/resources/application.yml`为准，通过systemd环境注入覆盖。至少设置：`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`（可空）、`DEVICE_CREDENTIAL_ENCRYPTION_KEY`（至少32字符）、`DEVICE_PLATFORM_BASE_URL`；启用模型调用时另设`PLANNING_MODEL_ENDPOINT`和`PLANNING_MODEL_API_KEY`。应用使用Flyway自动迁移，连接池和会话/超时配置由版本内application.yml管理；不要复制另一套不匹配的`application.yml`覆盖包内设置。通过root仅可读的EnvironmentFile或密钥管理器提供秘密值。

### 5.3 创建Systemd服务文件

**文件位置**: `/etc/systemd/system/airport-ai-app.service`

```ini
[Unit]
Description=Airport AI - Application Service
After=syslog.target network.target postgresql.service redis-server.service

[Service]
Type=simple
User=airportai
WorkingDirectory=/opt/airport-ai/app
EnvironmentFile=/etc/airport-ai/airport-ai.env
ExecStart=/usr/bin/java \
  -Xms1g -Xmx4g \
  -Dserver.port=8080 \
  -jar /opt/airport-ai/app/airport-ai-app-1.0.0.jar
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### 5.4 重载Systemd并启动服务

```bash
# 重载Systemd配置
sudo systemctl daemon-reload

# 启动应用服务
sudo systemctl start airport-ai-app

# 设置开机自启
sudo systemctl enable airport-ai-app

# 查看服务状态
sudo systemctl status airport-ai-app
```

`airport-ai.env`应由部署管理员创建并限制为`root:root`、`0600`，内容为KEY=VALUE格式；不要将含秘密的Environment行写入可普通用户读取的unit文件。修改unit或环境文件后执行`daemon-reload`并重启服务。

## 6. 前端应用部署

### 6.1 构建前端应用

**本地构建（开发机器）**：

```bash
# 进入前端项目目录
cd airport-ai-frontend

# 安装依赖
npm install

# 构建生产版本
npm run build

# 构建产物在 dist/ 目录
```

### 6.2 上传前端文件

```bash
# 上传构建产物到服务器
scp -r dist/* user@<服务器IP>:/opt/airport-ai/frontend/

# 设置权限
sudo chown -R www-data:www-data /opt/airport-ai/frontend/
```

### 6.3 配置Nginx

**文件位置**: `/etc/nginx/sites-available/airport-ai`

```nginx
server {
    listen 80;
    server_name <服务器IP或域名>;

    # 前端静态文件
    location / {
        root /opt/airport-ai/frontend;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # API代理（单体应用统一入口，对应附录B REST API）
    location /api/ {
        # 保留 /api 前缀，与Spring Controller的 /api/v1/... 路由一致
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 65s;   # 略大于规划模型60秒超时约束，避免代理层提前断开
    }

    # 预留代理配置；当前应用没有/ws/situation服务端实现，态势以REST轮询验收
    location /ws/ {
        proxy_pass http://localhost:8080/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 1800s;   # 对齐会话空闲30分钟策略
        proxy_send_timeout 1800s;
    }

    # 日志
    access_log /var/log/nginx/airport-ai-access.log;
    error_log /var/log/nginx/airport-ai-error.log;
}
```

### 6.4 启用Nginx配置

```bash
# 创建符号链接
sudo ln -s /etc/nginx/sites-available/airport-ai /etc/nginx/sites-enabled/

# 测试配置
sudo nginx -t

# 重新加载Nginx
sudo systemctl reload nginx
```

### 7.5 仿真运行时与P4演示控制

四类仿真运行时（`SMART_DISPLAY`、`BAGGAGE_SCANNER`、`FLIGHT_DELAY_BOARD`、`MOBILE_ROBOT`）分别以设备侧进程部署。平台需要从设备档案中的`accessEndpoint`访问运行时的HTTP接口；运行时需要访问平台报告地址。网络策略应仅开放两端实际需要的方向，设备令牌通过受控环境变量提供，不写入命令行记录或普通日志。

从项目根目录启动示例：设置`SIMULATOR_DEVICE_CODE`、`SIMULATOR_DEVICE_TOKEN`和`SIMULATED_DEVICE_TYPE`后运行`./scripts/start-simulator.ps1`（Windows）或按`simulator/`中的Spring Boot配置部署Linux服务。运行时端口和平台报告地址按`simulator/src/main/resources/application.yml`及部署环境配置。首次接入需在平台创建设备档案并完成真实健康握手，再创建/绑定代理；平台回调地址必须能从仿真运行时网络访问。

Linux示例unit（每个实例复制一份并使用独立EnvironmentFile）：

```ini
[Unit]
Description=Airport AI device simulator %i
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=airportai
WorkingDirectory=/opt/airport-ai/simulator
EnvironmentFile=/etc/airport-ai/simulators/%i.env
ExecStart=/usr/bin/java -jar /opt/airport-ai/simulator/device-simulator-runtime.jar
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

EnvironmentFile需由root创建并设为`0600`，写入本实例的`SIMULATOR_DEVICE_CODE`、`SIMULATOR_DEVICE_TOKEN`、`SIMULATED_DEVICE_TYPE`、`SIMULATOR_PORT`及`SIMULATOR_REPORT_URL`。先部署构建产物并确认用户有读取权限，再用`systemctl enable --now airport-ai-simulator@<实例名>`启动。该unit管理进程；控制台启停仍只改变仿真逻辑在线状态。

“仿真控制”页的启动/停止是实例逻辑状态控制：停止会报告离线、暂停心跳并拒绝新承接/执行命令；运行进程保持运行以便管理端恢复。该操作不会启动或终止操作系统进程，进程启动、崩溃拉起和重启需由systemd、容器编排或本地启动脚本管理。控制台同时支持成功、设备错误、超时及类型适用的无对象/目标丢失场景；演示结束后切回成功场景。

二维态势页调用`GET /api/v1/situation/snapshot`，前端按5秒间隔轮询。当前版本没有服务端`/ws/situation`实现，Nginx的WebSocket代理配置不代表该端点可用；演示和部署验收以REST快照为准。

三类演示任务从控制台的现有任务目标提交入口创建。真实多步骤执行还要求对应任务定义已启用、所需类型的代理在线，且外部规划模型已配置并可用；规划模型未配置时可验证提交入口，但不能据此宣称完成任务执行全链路。未连接PostgreSQL并执行Flyway迁移前，也不能判定数据库部署验收完成。

说明：初始管理员账号密码在4.1.3节数据初始化时以占位符哈希写入，部署完成后必须立即通过数据库直接更新或提供的初始化工具重设为实际密码，不得使用占位符对外提供访问。

### 8.2 关键配置项

#### 8.2.1 数据库连接池

```yaml
spring:
  datasource:
    hikari:
      minimum-idle: 5         # 最小空闲连接数
      maximum-pool-size: 30   # 最大连接数（对齐附录C第6.2节）
      connection-timeout: 30000  # 连接超时（毫秒）
      idle-timeout: 600000    # 空闲连接超时（毫秒）
```

#### 8.2.2 规划模型服务配置

对应附录A第3.4节统一调用抽象，通过环境变量注入，不写入配置文件明文提交代码仓库：

```bash
# 编辑服务文件
sudo vim /etc/systemd/system/airport-ai-app.service

# 添加Environment配置
[Service]
Environment="PLANNING_MODEL_ENDPOINT=https://your-planning-model-endpoint"
Environment="PLANNING_MODEL_API_KEY=your_api_key"
```

说明：规划模型服务可替换（对应附录A第3.4节），切换不同模型服务提供商仅需修改上述环境变量并重启服务，不需要改动业务代码。

## 9. 故障排查

### 9.1 常见问题

#### 9.1.1 服务无法启动

**问题**: 应用服务启动失败或立即退出

**排查步骤**:

```bash
# 查看服务状态
sudo systemctl status airport-ai-app

# 查看systemd日志
sudo journalctl -u airport-ai-app -n 100

# 查看应用日志
tail -100 /opt/airport-ai/logs/application.log
```

**常见原因**:
- 数据库连接失败（检查PostgreSQL是否启动、用户密码是否正确）
- 端口被占用（检查8080端口是否已被其他进程占用）
- 环境变量文件权限或键名错误（检查`/etc/airport-ai/airport-ai.env`和systemd日志，不要在诊断材料中输出秘密值）
- 规划模型服务环境变量未配置（应用启动本身不受影响，但调用时会失败并转基线降级，见附录D 7.2节故障2）

#### 9.1.2 数据库连接失败

**问题**: 应用日志显示数据库连接错误

**排查步骤**:

```bash
# 测试数据库连接
psql -h localhost -U airportai_user -d airport_ai

# 检查PostgreSQL状态
sudo systemctl status postgresql

# 查看PostgreSQL日志
sudo tail -100 /var/log/postgresql/postgresql-15-main.log
```

#### 9.1.3 前端页面无法访问

**问题**: 浏览器访问前端返回404或502

**排查步骤**:

```bash
# 检查Nginx状态
sudo systemctl status nginx

# 检查Nginx错误日志
sudo tail -100 /var/log/nginx/airport-ai-error.log

# 测试Nginx配置
sudo nginx -t

# 检查静态文件是否存在
ls -la /opt/airport-ai/frontend/
```

#### 9.1.4 规划模型服务调用异常

**问题**: 任务大量停留在监督判定中或转入高风险基线降级

**排查步骤**:

```bash
# 检查应用服务状态
sudo systemctl status airport-ai-app

# 查看应用日志中规划模型调用相关记录
grep "planning.model" /opt/airport-ai/logs/application.log

# 测试规划模型服务网络连通性
curl -I ${PLANNING_MODEL_ENDPOINT}
```

**处理方案**：对应5.4.6，系统已自动转基线降级或待人工处理，不影响平台其他功能（SRS_NF015）；排查外部模型服务本身状态后恢复，详见附录D第7.2节故障2。

### 9.2 日志收集

**收集诊断信息脚本**:

```bash
#!/bin/bash

DIAG_DIR="/tmp/airport-ai-diag-$(date +%Y%m%d_%H%M%S)"
mkdir -p $DIAG_DIR

echo "Collecting diagnostic information..."

# 系统信息
uname -a > $DIAG_DIR/system_info.txt
df -h > $DIAG_DIR/disk_usage.txt
free -h > $DIAG_DIR/memory_info.txt

# 服务状态
sudo systemctl status airport-ai-app > $DIAG_DIR/service_status.txt

# 进程信息
ps aux | grep java > $DIAG_DIR/java_processes.txt

# 网络信息
netstat -tlnp > $DIAG_DIR/network_ports.txt

# 应用日志
cp /opt/airport-ai/logs/*.log $DIAG_DIR/

# Nginx日志
sudo cp /var/log/nginx/airport-ai-*.log $DIAG_DIR/

# 打包
tar -czf $DIAG_DIR.tar.gz -C /tmp $(basename $DIAG_DIR)

echo "Diagnostic information collected: $DIAG_DIR.tar.gz"
```
