## 1. 监控体系架构

### 1.1 监控架构图

```
┌─────────────────────────────────────────────────┐
│            前端监控展示层（管理后台）              │
│         二维态势展示 + 系统监控页面                │
└──────────────────┬──────────────────────────────┘
                   │ WebSocket推送 + REST API查询
┌──────────────────┴──────────────────────────────┐
│          应用服务（单体部署，内置监控模块）        │
│  - 指标采集（Micrometer埋点）                    │
│  - 告警规则判定   - 告警推送                      │
└──────┬────────────────────────────┬─────────────┘
       │                            │
       ▼                            ▼
┌──────────────┐             ┌──────────────┐
│ PostgreSQL   │             │    Redis     │
│（业务指标、   │             │（缓存命中率、 │
│ 操作/异常记录）│             │ 会话状态）   │
└──────────────┘             └──────────────┘
```

说明：本项目为演示/验证性质单机部署（对应SRS_NF013），不引入独立时序数据库（InfluxDB）、消息队列（RabbitMQ）等组件；监控指标采集后直接通过应用内逻辑判定告警并推送，历史指标按需写入PostgreSQL供查询，不强制要求专用时序存储。

### 1.2 监控技术选型

| 组件 | 技术选型 | 用途 |
|---|---|---|
| 指标采集 | Spring Boot Actuator + Micrometer | 应用层指标暴露 |
| 指标存储 | PostgreSQL（按需落库）+ 内存态实时指标 | 历史指标查询；实时指标不强制持久化 |
| 告警推送 | WebSocket | 实时告警推送到前端（详见附录B第7节） |
| 日志收集 | 本地文件日志 | 应用日志写入本地文件 |
| 系统监控 | Micrometer | CPU、内存、磁盘、网络 |

## 3. 告警机制

### 3.1 告警规则

#### 3.1.1 系统资源告警

| 告警名称 | 触发条件 | 告警级别 | 处理建议 |
|---|---|---|---|
| CPU使用率过高 | CPU使用率 > 80% 持续5分钟 | WARNING | 检查是否有异常进程 |
| 内存使用率过高 | 内存使用率 > 85% 持续5分钟 | WARNING | 检查内存泄漏 |
| 磁盘空间不足 | 磁盘使用率 > 85% | ERROR | 清理日志、归档数据 |

#### 3.1.2 服务可用性告警

| 告警名称 | 触发条件 | 告警级别 | 处理建议 |
|---|---|---|---|
| 服务不可用 | 应用进程无响应 > 1分钟 | ERROR | 重启服务，检查日志 |
| API错误率过高 | API错误率 > 10% 持续1分钟 | ERROR | 检查日志，排查异常原因 |
| 数据库连接池耗尽 | 等待连接数 > 5 | ERROR | 检查慢查询，考虑扩大连接池 |

#### 3.1.3 业务告警（对齐V1.4正文核心链路风险点）

| 告警名称 | 触发条件 | 告警级别 | 处理建议 |
|---|---|---|---|
| 规划模型服务调用成功率低 | 成功率 < 95% 持续5分钟 | WARNING | 检查规划模型服务状态与网络连通性 |
| 规划模型服务超时 | 单次调用超过60秒判定超时 | WARNING | 检查外部模型服务响应；已自动转基线降级，不影响平台可用性 |
| 待人工处理任务积压 | 待人工处理任务数 > 3 | WARNING | 提示运行操作员及时处置 |
| 设备代理离线 | 心跳超时（默认30秒）未收到上报 | INFO | 对应5.2.3离线判断，检查设备网络连接 |
| 用户登录异常 | 登录失败率 > 20% 持续1分钟 | WARNING | 检查认证服务，关注是否有暴力破解尝试 |
| 账号锁定 | 连续3次密码错误触发锁定 | INFO | 提示系统管理员，如非本人操作需关注 |

### 3.2 告警分级

| 级别 | 说明 | 响应时间 | 通知方式 |
|---|---|---|---|
| INFO | 信息提示，无需立即处理 | 工作时间内处理 | WebSocket推送到管理界面 |
| WARNING | 警告，需关注 | 2小时内响应 | WebSocket推送 |
| ERROR | 错误，影响系统功能，需紧急处理 | 30分钟内响应 | WebSocket推送 |

### 3.3 告警推送

**推送渠道**: WebSocket推送到管理界面（复用附录B第7节态势/异常推送通道，消息类型为`EXCEPTION_ALERT`或新增`SYSTEM_ALERT`）

**推送格式**:
```json
{
  "type": "SYSTEM_ALERT",
  "level": "ERROR",
  "title": "规划模型服务调用超时",
  "message": "规划模型服务响应超过60秒，已转基线降级",
  "timestamp": "2026-09-07T10:30:00Z",
  "data": {
    "metric": "planning.model.call.timeout.count",
    "value": 1
  }
}
```

### 3.4 告警收敛

- **重复告警抑制**: 同一告警在5分钟内不重复推送
- **告警恢复通知**: 告警条件恢复后推送INFO级别恢复通知

## 4. 日志管理

### 4.1 日志级别

**配置策略**: INFO + WARN + ERROR

| 日志级别 | 用途 | 示例 |
|---|---|---|
| INFO | 正常业务流程关键节点 | 任务提交、任务完成、用户登录 |
| WARN | 可恢复的异常、降级操作 | 规划模型调用超时后转基线降级、设备离线后候选切换 |
| ERROR | 不可恢复的错误 | 数据库连接失败、应用启动失败、局部重新规划失败转人工处理 |

**不记录日志**: DEBUG/TRACE级别（生产环境关闭）

**安全约束**：日志中不得出现密码原值、设备接入凭据原值（对应SRS_NF001）；旅客真实身份信息不写入日志（对应SRS_NF003）。

### 4.2 日志存储

**存储方式**: 本地文件日志

**日志路径**: `/var/log/airport-ai/`

**日志文件命名**：
```
application-{yyyy-MM-dd}.log
例如: application-2026-09-07.log
```

**日志滚动策略**:
- **按日期滚动**: 每天生成新文件
- **文件大小限制**: 单文件最大500MB，超过则滚动
- **保留期限**: 与任务事件、操作记录一致，首期不做自动清理（对应TBD-08拍板结论）；如磁盘空间紧张，可手动归档

### 4.3 日志格式

**统一日志格式**:
```
{timestamp} {level} [{trace-id}] {thread} {class} : {message}
```

**示例**:
```
2026-09-07 10:30:15.123 INFO [req-abc123] [http-nio-8080-exec-1] com.airport.task.TaskController : 任务提交成功, taskId=TASK-20260907-0001
```

**字段说明**：

| 字段 | 说明 |
|---|---|
| timestamp | 时间戳（yyyy-MM-dd HH:mm:ss.SSS） |
| level | 日志级别（INFO/WARN/ERROR） |
| trace-id | 请求追踪ID（对应附录B 1.3节X-Request-ID） |
| thread | 线程名称 |
| class | 类名 |
| message | 日志消息 |

### 4.4 日志查询

**查询方式**：
- 通过SSH登录服务器，使用`grep`命令查询日志文件
- 示例: `grep "taskId=TASK-20260907-0001" /var/log/airport-ai/application-2026-09-07.log`

## 5. 备份策略

### 5.1 数据库备份

**备份方式**: 不需要自动备份（演示/验证环境规模，对应SRS_NF013）

**手动备份流程**：
1. 使用`pg_dump`命令导出PostgreSQL数据库
2. 存储位置: 本地其他磁盘（非系统盘）
3. 执行命令:
   ```bash
   pg_dump -U postgres -d airport_ai > /backup/airport_ai_$(date +%Y%m%d).sql
   ```

**备份内容**: 全部数据（用户、设备、能力、模板、任务、事件、操作记录等）

**备份保留**: 手动管理，建议保留最近3次备份

### 5.2 配置文件备份

**备份方式**: 手动备份

**备份内容**:
- `application.yml`（应用配置文件，含规划模型服务地址）
- `.env`（环境变量文件，含规划模型服务凭据、数据库连接信息）

**备份存储**: 本地其他磁盘 + 版本控制系统（Git，凭据类内容不入库）

## 6. 运维操作规程

### 6.1 服务启动

**启动顺序**:
1. 启动基础服务: PostgreSQL、Redis
2. 启动应用服务

**启动命令（示例）**:
```bash
# 启动PostgreSQL
sudo systemctl start postgresql

# 启动Redis
sudo systemctl start redis

# 启动应用服务
sudo systemctl start airport-ai-app
```

### 6.2 服务停止

**停止顺序**:
1. 停止应用服务
2. 停止基础服务（如需维护）

**停止命令（示例）**:
```bash
sudo systemctl stop airport-ai-app
```

### 6.3 服务重启

**重启场景**:
- 配置文件更新（如规划模型服务地址变更）
- 代码版本更新
- 服务异常需要重启

**重启命令（示例）**:
```bash
sudo systemctl restart airport-ai-app
```

### 6.4 日志查看

**实时日志查看**:
```bash
tail -f /var/log/airport-ai/application-2026-09-07.log
```

**历史日志查询**:
```bash
grep "ERROR" /var/log/airport-ai/application-2026-09-07.log
```

### 6.5 数据库维护

**慢查询分析**:
```sql
SELECT * FROM pg_stat_statements ORDER BY total_exec_time DESC LIMIT 10;
```

**连接数查询**:
```sql
SELECT count(*) FROM pg_stat_activity;
```

## 7. 故障处理流程

### 7.1 故障响应流程

```
┌─────────────┐
│ 告警触发    │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 初步诊断    │ ← 查看日志、监控指标
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 影响评估    │ ← 判断故障级别（P0/P1/P2/P3，定义见附录E第6.2节）
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 应急处理    │ ← 重启服务；外部规划模型异常时平台自动降级，不影响其他功能
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 根因分析    │ ← 深入排查，定位根本原因
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 永久修复    │ ← 代码修复、配置优化
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 复盘总结    │ ← 文档化问题与解决方案
└─────────────┘
```

### 7.2 常见故障处理

#### 故障1: 应用服务不可用

**症状**: 管理后台无响应或返回502错误

**诊断步骤**:
1. 检查服务进程状态: `systemctl status airport-ai-app`
2. 检查服务日志: `tail -f /var/log/airport-ai/*.log`
3. 检查系统资源: `top`, `df -h`

**处理方案**:
- 重启服务 `systemctl restart airport-ai-app`
- 如系统资源耗尽，清理日志或排查异常进程
- 如数据库连接耗尽，重启数据库或扩大连接池

#### 故障2: 规划模型服务不可用或超时

**症状**: 任务大量停留在"监督判定中"或转入高风险基线降级

**诊断步骤**:
1. 查看规划模型服务调用成功率与超时指标（planning.model.call.*）
2. 检查外部规划模型服务网络连通性与凭据有效性

**处理方案**:
- 对应5.4.6，系统已自动转基线降级或待人工处理，不下发设备指令，平台其他功能不受影响（对应SRS_NF015）
- 排查外部模型服务本身故障后恢复；如需临时切换为其他模型服务，按附录A 3.4节配置切换

#### 故障3: 任务大量转入待人工处理

**症状**: task.manual_pending.count告警持续触发

**诊断步骤**:
1. 查询待人工处理任务列表及原因码：`SELECT * FROM tasks WHERE status='PENDING_MANUAL' ORDER BY updated_at DESC LIMIT 100`
2. 检查任务事件时间线，定位是监督服务不可用、无可用基线模板还是基线执行失败

**处理方案**:
- 如为无可用基线模板，检查对应任务族模板是否已启用
- 如为设备普遍离线，检查设备网络连接
- 逐一在任务详情中人工处置（转基线执行、重试规划、置为失败或终止）
