## 1. 响应时间指标

### 1.1 API响应时间（对应SRS_NF007：一般页面95%请求≤1秒）

| 接口类型 | 目标响应时间 | 最大可接受时间 | 测试条件 |
|---|---|---|---|
| 用户登录 | < 500ms | < 1s | 正常网络环境 |
| 查询任务列表（分页） | < 300ms | < 1s | 单页20条记录 |
| 查询任务详情 | < 300ms | < 1s | 单条记录查询，含事件时间线 |
| 提交任务目标（不含规划） | < 500ms | < 1s | 仅目标解析与信息补全校验 |
| 二维态势快照查询 | < 500ms | < 1s | 20个设备全量态势 |
| 设备档案/能力管理类接口 | < 300ms | < 1s | 单条记录增删改查 |
| 操作记录/事件查询 | < 500ms | < 1s | 单页20条记录 |

### 1.2 任务规划链路响应时间（对应SRS_NF008）

| 处理类型 | 目标响应时间 | 最大可接受时间 | 说明 |
|---|---|---|---|
| 目标理解与信息补全判定 | < 1s | < 2s | 本地处理，不含外部模型调用 |
| 规划模型服务调用（候选计划生成） | < 3s | 60s超时 | 外部模型服务调用，超时后转基线降级（5.4.6），不得下发设备指令 |
| 三类校验（结构/能力/约束） | < 500ms | < 1s | 单个计划版本 |
| 监督智能体风险判定 | < 1s | < 3s | 含确定性规则匹配与风险信号计算 |
| 基线模板匹配 | < 500ms | < 1s | — |
| 局部重新规划全链路 | < 5s | 60s超时 | 复用规划模型调用超时约束 |

### 1.3 数据库操作时间

| 操作类型 | 目标时间 | 最大可接受时间 | 测试条件 |
|---|---|---|---|
| 单表简单查询 | < 50ms | < 100ms | 主键查询，数据量<10万条 |
| 多表关联查询 | < 200ms | < 500ms | 2-3表JOIN，结果集<1000条 |
| 数据插入 | < 100ms | < 300ms | 单条记录插入 |
| 任务事件追加写入 | < 100ms | < 300ms | 仅追加，不支持修改删除 |
| 数据更新 | < 100ms | < 300ms | 单条记录更新 |

## 2. 并发能力指标

### 2.1 用户与设备并发

| 指标 | 目标值 | 说明 |
|---|---|---|
| 同时在线后台用户数 | ≤ 10人 | 系统管理员+运行操作员+配置管理员合计 |
| 接入设备或仿真体数量 | 首期演示≤10个，系统性能设计上限20个 | 覆盖智慧航显、智能行李测量设备、航延屏、移动服务机器人、仿真体5类；接入上限可配置（TBD-01） |
| 并发API请求数（QPS） | < 30 QPS | 单机部署，混合接口压测 |
| WebSocket并发连接数 | ≤ 10 | 与在线用户数一致，用于态势与告警推送 |

### 2.2 任务并发（对应SRS_NF006）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 同时执行任务数（并发任务） | ≤ 10个 | 硬性上限，超出后新任务进入待规划队列等待 |
| 单任务最大局部重新规划次数 | 1次 | 每个任务全生命周期内最多触发一次（5.5.4） |
| 单个候选计划最大步骤数 | 5个可执行步骤 | 条件节点不计数（5.4.3） |

### 2.3 设备状态上报并发（对应SRS_NF009）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 支持设备按周期上报数量 | 20个设备按15秒周期上报 | 对应7.2.2平台统一设备接口，默认周期15秒可配置5~60秒 |
| 心跳超时判定阈值 | 默认30秒，可配置10~120秒 | 超时标记离线、退出候选集合、生成离线异常事件（5.2.3） |

## 3. 数据存储指标

### 3.1 数据保留期限（TBD-08拍板结论）

| 数据类型 | 保留策略 | 说明 |
|---|---|---|
| 任务事件（5.7.1） | 首期不做自动清理，保留全部演示期数据 | 事件仅可追加，不可修改或删除 |
| 操作记录（5.7.2） | 首期不做自动清理，保留全部演示期数据 | — |
| 异常记录（5.5.3） | 首期不做自动清理，保留全部演示期数据 | — |
| 规划上下文快照 | 随任务保留，不单独清理 | 关联对应任务查询 |

说明：数据保留周期为TBD-08拍板结论，首期演示场景数据量有限（≤10并发任务、≤20接入对象），暂不设自动清理机制；后续如投入长期运行环境，需重新评估保留策略并走变更评审。

### 3.2 存储容量规划（单机部署规模）

| 存储类型 | 初始容量 | 预计增长速率 | 扩容阈值 |
|---|---|---|---|
| PostgreSQL数据库 | 20GB | 演示期数据量小，按季度评估 | 达到80% |
| Redis缓存 | 1GB | 稳定（会话+态势快照缓存） | 达到80% |

说明：本项目无视频/图像类大对象存储需求，不涉及对象存储容量规划。

## 4. 规划模型调用性能指标

### 4.1 规划模型服务调用性能

| 指标 | 目标值 | 最大值 | 说明 |
|---|---|---|---|
| 单次调用延迟 | < 3s | 60s超时 | 超时后转5.4.6高风险基线降级流程，不下发设备指令 |
| 调用频次上限 | 受并发任务≤10个约束 | — | 与任务并发指标一致，不单独设QPS上限 |
| 模型置信度阈值（低置信度判定） | < 0.8 | — | TBD-04拍板结论，作为监督判定风险信号之一 |
| 上下文接近过期判定阈值 | > 60秒未刷新 | — | TBD-04拍板结论 |

### 4.2 规划链路成功率

| 指标 | 目标值 | 说明 |
|---|---|---|
| 规划模型服务调用成功率 | > 95% | 排除网络抖动；失败或超时均转基线降级，不视为任务失败 |
| 三类校验一次通过率 | > 90% | 演示场景下的合理预期，用于评估基线模板与规则库覆盖是否充分 |
| 任务自动完成率（不经人工处理） | > 85% | 低风险自动执行+高风险基线降级后完成的任务比例 |

说明：本项目不涉及人脸识别、行为分析、实时视频分析等AI处理场景，相关指标已删除。

## 5. 系统可用性指标

### 5.1 可用性目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 演示环境连续运行时长 | ≥ 8小时无导致核心流程中断的严重故障 | SRS_NF011，验收基线 |
| 部署形态 | 一套服务器或开发验证环境 | 不要求高可用集群与异地容灾（SRS_NF013） |
| 外部服务（规划模型/监督服务）不可用时平台可用性 | 平台保持可访问，按基线降级或转人工处理 | SRS_NF015，不得因外部服务异常导致平台不可访问 |

### 5.2 故障响应与降级时间

| 场景 | 响应/降级时间 | 说明 |
|---|---|---|
| 规划模型服务超时 | 60秒内判定超时并转基线降级 | 对应SRS_NF008 |
| 监督服务不可用 | 判定超时后立即转待人工处理 | 对应5.4.5异常路径4b |
| 设备心跳超时 | 默认30秒内标记离线 | 对应5.2.3 |
| 演示环境故障恢复 | 无强制RTO/RPO指标 | 非高可用场景，故障恢复以人工介入为主，不设自动化恢复时间目标 |

说明：本项目为演示/验证性质单机部署，不设P0~P3故障分级响应体系与RTO/RPO指标，相关内容已删除。

## 7. 性能测试方法

### 7.1 压力测试场景

#### 场景1：用户登录压力测试

- **目标**: 验证10并发用户登录（SRS_NF006上限）
- **工具**: JMeter
- **步骤**:
  1. 配置10个线程（虚拟用户）
  2. 每个线程循环执行登录操作10次
  3. 记录响应时间、成功率
- **通过标准**: 95%请求响应时间≤1s，成功率>99%

#### 场景2：设备并发心跳压测

- **目标**: 验证20个设备同时按15秒周期上报状态（SRS_NF009，TBD-01系统上限）
- **工具**: 自定义压测脚本模拟设备代理批量上报
- **步骤**:
  1. 模拟20个设备代理，按15秒周期并发上报状态
  2. 持续压测30分钟
  3. 监控上报接口响应时间与数据库写入延迟
- **通过标准**: 上报接口响应时间<1s，无因并发上报导致的数据丢失或心跳误判离线

#### 场景3：任务规划链路并发压测

- **目标**: 验证10个并发任务同时经历规划-校验-监督判定全链路（SRS_NF006）
- **工具**: 自定义压测脚本，模拟并发提交任务目标
- **步骤**:
  1. 同时提交10个不同任务族的任务目标
  2. 记录每个任务从提交到进入待分配/降级执行中的耗时
  3. 观察是否有任务因资源竞争超时或误判为资源冲突临界（高风险规则RULE_RESOURCE_CRITICAL）
- **通过标准**: 全部任务在规划模型60秒超时约束内完成判定，无因平台自身资源竞争导致的误判

#### 场景4：外部规划模型服务不可用降级测试

- **目标**: 验证规划模型服务不可用时平台仍可用（SRS_NF015）
- **工具**: 手动关闭规划模型服务/模拟服务返回超时
- **步骤**:
  1. 停用规划模型服务或注入超时
  2. 提交任务目标，观察是否在60秒内转入高风险基线降级或待人工处理
  3. 验证平台其他功能（设备管理、态势展示、历史任务查询）不受影响
- **通过标准**: 任务在60秒内转入降级或待人工处理，不下发任何设备指令；平台其他功能响应正常
