## 1. 整体架构设计

### 1.1 架构风格

本系统采用**单体应用+模块化分层架构**，与SRS_NF013"部署环境为一套服务器或开发验证环境即可，不要求高可用集群与异地容灾"的规模定位相匹配，不采用微服务拆分。业务功能按领域划分为独立模块，模块间通过内部接口（见7.2.1）协作，对外通过统一REST API暴露。

**架构特点**：

- **单体部署**: 全部业务模块部署于同一应用进程，降低运维复杂度，匹配演示/验证环境规模
- **模块内聚**: 设备接入、任务规划、执行监督等模块职责边界清晰，内部接口调用不绕过三类校验与运动安全边界约束
- **外部模型可替换**: 通过统一的规划模型调用接口对接外部规划模型服务，支持模型服务替换或本地模型部署，不绑定具体厂商
- **风险闸门集中**: 三类校验（结构/能力/约束）与监督智能体风险判定为硬性闸门，任何模块不得绕过

### 1.2 分层架构

```
┌──────────────────────────────────────────┐
│          展现层 (Presentation)            │
│    Vue.js 3.x + Ant Design (PC Web)      │
└─────────────┬────────────────────────────┘
              │ HTTPS / WebSocket
┌─────────────┴────────────────────────────┐
│          接口层 (API Layer)               │
│   路由、认证、权限校验、日志               │
└─────────────┬────────────────────────────┘
              │
┌─────────────┴────────────────────────────┐
│          业务层 (Business Modules)        │
│  用户认证、设备接入与代理管理、能力边界    │
│  管理、基线模板管理、任务规划、三类校验、  │
│  监督判定、执行监督、过程追溯              │
└─────────────┬────────────────────────────┘
              │
┌─────────────┴────────────────────────────┐
│          数据层 (Data Layer)              │
│         PostgreSQL、Redis                │
└──────────────────────────────────────────┘
              │
┌─────────────┴────────────────────────────┐
│          外部集成层 (External Services)   │
│    规划模型服务、设备统一接口（模拟适配器）│
└──────────────────────────────────────────┘
```

## 2. 模块划分

### 2.1 核心业务模块清单

对应V1.4正文第五章功能需求，模块划分不等同于微服务拆分，均部署于同一应用进程内。

| 模块名称 | 职责边界 | 对应正文章节 |
|---|---|---|
| 用户认证模块 | 登录、会话管理、密码锁定、三类角色权限校验 | 5.1.1 |
| 设备接入与代理管理模块 | 设备档案、连接测试、设备代理生命周期、心跳与离线判断 | 5.2.1~5.2.3 |
| 设备类型能力边界管理模块 | 设备类型能力边界维护、能力模板库、越界校验 | 5.2.4A |
| 设备能力画像管理模块 | 能力定义、模拟调用测试、能力启用停用 | 5.2.4 |
| 设备代理消息模块 | 六类业务消息处理、运动安全字段拦截 | 5.2.5 |
| 基线模板管理模块 | 模板定义、试运行、启用、预置任务族保护 | 5.3.1、5.3.2 |
| 任务规划模块 | 目标理解、规划上下文构建、候选计划生成（调用外部规划模型服务） | 5.4.1~5.4.3 |
| 三类校验模块 | 结构/能力/约束校验，硬性闸门 | 5.4.4 |
| 监督判定模块 | 确定性高风险规则匹配、风险信号计算、基线降级触发 | 5.4.5、5.4.6 |
| 执行监督模块 | 步骤设备匹配、指令下发、异常识别恢复、局部重新规划、人工终止 | 5.5.1~5.5.6 |
| 业务场景模块 | 旅客服务任务定义、超规行李处置、特殊旅客服务、航班变更应对、二维态势展示 | 5.6.1~5.6.5 |
| 过程追溯模块 | 任务事件写入（仅追加）、操作记录 | 5.7.1、5.7.2 |

### 2.2 模块间调用关系

对应V1.4正文7.2.1节内部接口，均为模块间调用而非跨服务网络调用：

- 任务规划模块 → 设备接入与代理管理模块（规划上下文查询接口）
- 任务规划模块 → 三类校验模块（计划校验接口，硬性闸门）
- 任务规划模块 → 监督判定模块（监督判定接口）
- 监督判定模块 → 基线模板管理模块（基线模板匹配接口）
- 全部业务模块 → 过程追溯模块（任务事件写入接口，仅可追加）
- 设备能力画像管理模块 → 设备类型能力边界管理模块（能力边界查询接口，越界校验）

### 2.3 外部集成

| 集成对象 | 调用方向 | 协议 | 说明 |
|---|---|---|
| 规划模型服务 | 任务规划模块 → 外部服务 | HTTPS | 单次请求60秒超时；模型可替换，支持外部服务或本地模型部署；模拟模型仅用于接口自测，不作为验收基线 |
| 设备（模拟适配器） | 平台 ↔ 设备代理 | HTTP | 首期以模拟适配器实现，新增同类设备不需修改业务功能代码 |

## 3. 技术栈详细说明

### 3.1 后端技术栈

| 技术组件 | 版本 | 用途 |
|---|---|---|
| Java | JDK 17+ | 开发语言 |
| Spring Boot | 3.2.x | 应用框架 |
| Spring Security | 6.2.x | 安全认证 |
| Spring Data JPA | 3.2.x | ORM框架 |

### 3.2 前端技术栈

| 技术组件 | 版本 | 用途 |
|---|---|---|
| Vue.js | 3.4.x | 前端框架 |
| Ant Design Vue | 4.x | UI组件库 |
| ECharts | 5.5.x | 二维态势展示数据可视化 |
| Axios | 1.6.x | HTTP客户端 |
| Vue Router | 4.x | 路由管理 |
| Pinia | 2.x | 状态管理 |

### 3.3 数据存储技术栈

| 技术组件 | 版本 | 用途 | 数据类型 |
|---|---|---|---|
| PostgreSQL | 15.x | 关系型数据库 | 用户、设备、能力、模板、任务、事件等结构化数据（详见数据库设计说明书） |
| Redis | 7.2.x | 缓存+会话 | 用户会话信息、二维态势快照缓存 |

说明：本项目无视频/图像类大对象存储需求，不引入对象存储组件；不涉及时序指标大规模采集场景，暂不引入独立时序数据库，运维监控相关指标存储方式见附录D。

### 3.4 外部规划模型服务集成

**统一调用抽象**：

```java
// 规划模型服务调用接口抽象，屏蔽具体模型服务差异
public interface PlanningModelService {
    PlanningResponse generatePlan(PlanningRequest request);
}

// 实现类按接入的具体模型服务替换，接口契约见附录B 5.1节
public class ExternalPlanningModelServiceImpl implements PlanningModelService {
    @Override
    public PlanningResponse generatePlan(PlanningRequest request) {
        // 通过HTTPS调用外部规划模型服务，单次请求60秒超时
        // 超时或不可用时抛出异常，由任务规划模块转5.4.6高风险基线降级
    }
}

// 模拟实现，仅用于接口自测，不作为验收基线
public class MockPlanningModelServiceImpl implements PlanningModelService {
    @Override
    public PlanningResponse generatePlan(PlanningRequest request) {
        // 返回固定或规则生成的模拟候选计划
    }
}
```

**统一配置管理**：
- 规划模型服务地址、认证凭据通过配置文件或环境变量管理，不提交代码仓库
- 支持通过配置切换实际接入的模型服务实现
- 调用失败或超时统一转入5.4.6高风险基线降级流程，不重试超过约束（重试次数上限见执行监督模块相关约束）

## 4. 数据架构

### 4.1 数据库设计原则

- **单库多表**: 全部业务数据存储于同一PostgreSQL实例，按业务领域划分表结构，详细字段设计见《数据库设计说明书》
- **事件不可变**: 任务事件表仅支持追加写入，不提供修改或删除接口（对应5.7.1）
- **审计留痕**: 操作记录表记录全部管理操作，凭据类字段掩码存储

### 4.2 核心数据实体

| 数据实体 | 说明 | 存储介质 |
|---|---|---|
| 用户账号 (users) | 账号、角色、密码锁定状态字段 | PostgreSQL |
| 设备档案 (devices) | 设备类型、区域、接入参数 | PostgreSQL |
| 设备代理 (device_agents) | 代理状态、在线状态、工作状态 | PostgreSQL |
| 设备类型能力边界 (device_type_capability) | 设备类型支持的能力类型清单 | PostgreSQL |
| 能力模板 (capability_template) | 能力类型对应的标准输入输出模板 | PostgreSQL |
| 设备能力 (device_capabilities) | 设备实例已启用的能力实例 | PostgreSQL |
| 基线服务模板 (baseline_templates) | 模板步骤、版本、试运行/启用状态 | PostgreSQL |
| 确定性高风险规则 (risk_rules) | 规则内容、版本、启用状态 | PostgreSQL |
| 任务 (tasks) | 任务目标、状态、计划版本关联 | PostgreSQL |
| 计划版本 (plan_versions) | 候选计划步骤、来源、冻结时间 | PostgreSQL |
| 任务事件 (task_events) | 全生命周期事件时间线，仅追加 | PostgreSQL |
| 操作记录 (operation_logs) | 用户操作审计记录 | PostgreSQL |

详细字段、类型、约束参见《数据库设计说明书》。

### 4.3 缓存策略

**Redis缓存用途**：
- 用户会话信息（空闲30分钟失效，对应SRS_NF002）
- 二维态势快照缓存（默认5秒刷新、上限15秒，对应5.6.2、TBD-02拍板结论）
- 规划上下文快照缓存（供同一任务链条内复用，对应5.4.2）

**缓存更新策略**：
- **Cache-Aside模式**: 查询时先查缓存，未命中则查数据库并更新缓存
- **过期策略**: 会话缓存TTL与会话空闲策略一致（30分钟滑动过期）；态势快照缓存TTL对齐刷新周期（默认5秒）

## 5. 通信机制

### 5.1 REST API设计规范

**URL设计**：
```
GET    /api/v1/tasks          # 查询任务列表
POST   /api/v1/tasks          # 提交任务目标
GET    /api/v1/tasks/{id}     # 查询任务详情
POST   /api/v1/tasks/{id}/terminate  # 人工终止任务
```

**统一响应格式**：
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-09-07T10:30:00Z"
}
```

详见**附录B：接口设计规范**。

### 5.2 内部模块调用

模块间调用为进程内方法调用或内部HTTP接口（见附录B第4节内部接口），不引入独立消息队列组件。任务状态变更、异常事件等通过任务事件写入接口（5.7.1）同步记录，前端通过WebSocket通道或轮询感知变化。

### 5.3 实时通信（WebSocket）

**用途**: 二维态势展示增量推送、任务状态更新、异常告警推送（详见附录B第7节）

**连接管理**：
- 用户登录后建立WebSocket连接
- 服务端推送任务状态更新、设备代理状态变化、异常事件、待人工处理提醒
- 连接空闲30分钟自动断开，与会话空闲策略一致（对应SRS_NF002）

## 6. 安全架构

### 6.1 认证与授权

**认证方式**: 账号+密码（1~32位账号，8~32位密码）

**会话机制**: 服务端会话（Token）
- **有效期**: 会话空闲30分钟后失效（对应SRS_NF002），非固定有效期
- **刷新机制**: 会话内有操作则滑动延续；空闲超时后需重新登录，不支持自动刷新
- **存储位置**: 前端内存/会话存储，服务端Redis维护会话状态

**权限模型**: RBAC（基于角色的访问控制），权限由服务端逐接口校验，不依赖前端菜单隐藏（对应SRS_NF004）

**角色定义**（对应5.1.1）：

| 角色 | 权限范围 |
|---|---|
| 系统管理员 | 账号管理（创建、重置密码、停用、解锁）、全部功能查看权限 |
| 运行操作员 | 任务提交、任务监控、异常处置、人工终止 |
| 配置管理员 | 设备管理、能力边界与画像管理、基线模板管理、确定性高风险规则配置 |

说明：旅客为间接用户，不登录系统；本期不提供自助注册、找回密码、单点登录和多因子认证。

### 6.2 数据安全

- **密码存储**: 不可逆摘要（加盐）存储，数据库与日志中不得出现密码原值（对应SRS_NF001）
- **传输**: 采用HTTPS（对应7.2.2外部接口要求）；具体部署网络边界按实施环境确定
- **敏感数据脱敏**: 旅客真实身份信息不保存，演示使用虚构或脱敏数据；提交给规划模型的内容须脱敏（对应SRS_NF003）
- **运动安全边界**: 平台不得下发运动安全控制指令，设备代理消息模块对含运动安全字段的消息执行拦截并记录（对应SRS_NF005、5.2.5）

### 6.3 审计日志

**记录范围**: 登录、登出、设备配置、能力启停、模板启停、任务定义变更、风险规则变更、人工终止、人工处置（对应5.7.2操作记录）

**保留期限**: 首期不做自动清理，保留全部演示期数据（对应TBD-08拍板结论）

**日志内容**: 操作时间、操作人、角色、操作类型、操作对象、结果、来源IP、详情（凭据字段掩码展示）

## 7. 部署架构

### 7.1 部署方式

**部署形态**: 一套服务器或开发验证环境即可，满足原型部署即可，不要求高可用集群与异地容灾（对应SRS_NF013）

**部署拓扑**：
```
┌───────────────────────────────────────┐
│         VM (Ubuntu 22.04 LTS)         │
│                                       │
│  ┌─────────────────────────────────┐ │
│  │  应用服务 :8080                  │ │
│  │  （用户认证/设备接入/任务规划/    │ │
│  │   三类校验/监督判定/执行监督/     │ │
│  │   基线模板/过程追溯 等模块）       │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │  PostgreSQL :5432               │ │
│  │  Redis :6379                    │ │
│  └─────────────────────────────────┘ │
└───────────────────────────────────────┘
        │ HTTPS
        ▼
┌───────────────────────────────────────┐
│  规划模型服务（外部，可替换）           │
└───────────────────────────────────────┘
```

### 7.2 服务管理

- **进程管理**: Systemd（Linux服务方式启动应用进程）
- **日志管理**: 本地文件日志
- **配置管理**: application.yml配置文件，规划模型服务地址与凭据通过环境变量管理

## 8. 可扩展性说明

### 8.1 当前版本规模定位

当前版本面向演示/验证场景，按SRS_NF006约束设计：并发后台用户不超过10人，接入设备或仿真体不超过20个，并发任务不超过10个。不采用微服务拆分与集群化部署，容量规划详见附录C。

### 8.2 可扩展点

- **设备接入**: 平台统一设备接口以模拟适配器实现，新增同类设备不需修改业务功能代码（对应SRS_NF014）
- **规划模型服务**: 通过统一调用接口对接，支持替换为不同的外部模型服务或本地模型部署，不绑定具体厂商
- **业务场景扩展**: 旅客服务任务定义支持在预置三类任务族（超规行李处置、特殊旅客服务、航班变更应对）之外新增扩展任务族（对应5.6.1）

### 8.3 后续演进方向（超出本期范围）

若未来投入长期生产环境运行，需重新评估以下事项，不属于本期设计范围：
- 是否需要拆分为微服务架构以支持独立扩展
- 是否需要引入消息队列以支持更大规模的异步事件处理
- 数据库是否需要主从/集群化部署
- 高可用与异地容灾方案
