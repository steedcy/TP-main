# 设备仿真通信契约（P0）

- 契约版本：1.0（项目内实现基线）
- 日期：2026-10-13
- 依据：SRS V1.4 第5.2、5.5、7.2、8.2、8.4节；仓库附录B V2.0；附录F；附录E
- 目的：冻结平台代理与独立仿真运行时之间的身份、状态、命令、反馈和能力参数契约，作为 P1 编码及验收依据。

## 1. 冻结决策

1. 设备代理是平台规划、执行监督和基线服务访问设备的唯一入口。任务执行器不得直接调用仿真驱动。
2. 四类仿真设备档案的 `deviceTypeCode` 固定为 `SIMULATOR`，`simulatedDeviceType` 必须且只可为 `SMART_DISPLAY`、`BAGGAGE_SCANNER`、`FLIGHT_DELAY_BOARD`、`MOBILE_ROBOT` 之一。仿真档案拥有 `CAP_SIM_STATUS`，调度能力继承自模拟设备类型，不把五类设备都混成同一“全能设备”。
3. 通信采用设备侧可部署的 HTTP/JSON 适配器。平台从设备档案的 `accessEndpoint` 向仿真运行时发起健康检查/命令；仿真运行时向平台上报状态/响应。协议 DTO 与传输方式分离，未来可替换 WebSocket，而不改任务消息语义。
4. 身份握手在代理创建前按 `deviceCode` 完成；代理创建后平台将生成的 `agentCode` 绑定给仿真运行时。绑定成功后，上行状态和任务响应使用该 `agentCode`。这样连接测试不依赖一个尚不存在的代理编号。
5. 对附录B定义的 `/device-api/v1/agents/{agentId}/report` 和 `/commands` 保持字段语义；增加 `reportType` 判别字段以复用 `/report` 并保证状态、承接响应、执行反馈可区分。旧 `/api/v1/device-agents/...` 路由作为兼容入口适配到同一 service，禁止出现第二套业务状态推进逻辑。
6. 所有平台下发命令都带 `commandId`。第一次发送和一次自动重试使用同一 `commandId`；仿真运行时需对已处理命令幂等。
7. 仿真时延默认 500ms（附录F `CAP_SIM_STATUS`）。耗时类能力返回业务逻辑耗时，但不要求演示等待真实的 5—1800 秒；实例可配置时延倍率。异常场景由显式注入驱动，不依赖随机失败。
8. 附录F的行李设备约束“单次测量不超过30秒”严于参数 `timeout` 的10—60秒范围。契约取两者较严者：实测运行预算最多30秒；若请求期限更短则按请求期限超时。尺寸超规定义为三边之和 `>158cm`，重量超规为 `>32kg`，等于阈值不超规。
9. 设备接口通过独立设备令牌认证（`Authorization: Bearer ...`）；不得复用后台用户 JWT。演示数据使用合成旅客/航班信息，不写入真实旅客身份。
10. 业务消息禁止包含运动安全控制字段。机器人能力只接收业务目的地、路线偏好、陪同模式等高层意图；禁止速度、加速度、姿态、坐标路径点、避障距离、急停、限速、失联停靠等字段。

## 2. 调用方向与端点

| 方向 | 方法和路径 | 用途 | 身份键 |
|---|---|---|---|
| 平台 → 仿真运行时 | `GET {accessEndpoint}/device-api/v1/health?nonce={nonce}` | 代理创建前连接测试；返回设备身份、有效状态快照、协议版本和能力 | 设备令牌 + `deviceCode` |
| 平台 → 仿真运行时 | `POST {accessEndpoint}/device-api/v1/agents/{agentCode}/binding` | 代理创建成功后告知代理编号、报告地址和心跳周期；绑定成功才启动周期上报 | 设备令牌 |
| 仿真运行时 → 平台 | `POST /device-api/v1/agents/{agentCode}/report` | 上报 `STATUS`、`TASK_RESPONSE` 或 `EXECUTION_FEEDBACK` | 设备令牌 + `agentCode` |
| 平台 → 仿真运行时 | `POST {accessEndpoint}/device-api/v1/agents/{agentCode}/commands` | 下发业务命令或取消业务任务 | 设备令牌 + `agentCode` |
| 平台内部模块 → 设备代理 service | `POST /internal/v1/device-agent/messages` | 附录B六类统一消息的唯一内部入口 | 平台内部调用身份 |

`accessEndpoint` 对仿真实例必须为设备侧 HTTP 服务的基址；路径拼接只在适配器内完成。连接测试要求 `/health` 返回与请求 nonce 一致的响应、匹配档案 `deviceCode`、合法 `simulatedDeviceType` 及格式有效的状态快照。平台根据该快照记录连接测试结果。代理创建成功后，平台发送 binding；仿真器开始上报，收到首个合法在线状态后成为在线候选。

### 2.1 健康握手响应

```json
{
  "protocolVersion": "1.0",
  "nonce": "n-8b12f5",
  "deviceCode": "SIM-DISPLAY-01",
  "simulatedDeviceType": "SMART_DISPLAY",
  "onlineStatus": "ONLINE",
  "workStatus": "IDLE",
  "location": { "x": 120.5, "y": 88.2, "zone": "T2-B区" },
  "capabilities": ["CAP_INFO_DISPLAY", "CAP_FLIGHT_UPDATE", "CAP_NAVIGATION"],
  "reportedAt": "2026-10-13T03:00:00Z"
}
```

### 2.2 Binding 请求和响应

```json
{
  "deviceCode": "SIM-DISPLAY-01",
  "agentCode": "AGT-7B7A31F2",
  "reportUrl": "http://platform:8080/device-api/v1/agents/AGT-7B7A31F2/report",
  "heartbeatIntervalSeconds": 15,
  "heartbeatTimeoutSeconds": 30
}
```

仿真运行时仅在绑定成功后开始上报。重放相同绑定幂等；同一 `deviceCode` 绑定到不同启用代理时拒绝并报告 `BINDING_CONFLICT`。

## 3. 通用报文

### 3.1 下行命令

```json
{
  "commandId": "CMD-20261013-000001",
  "commandType": "EXECUTE_CAPABILITY",
  "attemptNo": 0,
  "taskId": "TASK-20261013-0001",
  "stepSeq": 1,
  "capabilityType": "CAP_INFO_DISPLAY",
  "inputParams": {
    "contentType": "TEXT",
    "contentData": "登机口已变更为A05",
    "displayDuration": 30,
    "displayPosition": "FULL_SCREEN"
  },
  "issuedAt": "2026-10-13T03:00:01Z",
  "deadline": "2026-10-13T03:01:01Z"
}
```

`commandType` 取 `TASK_ACCEPT`、`EXECUTE_CAPABILITY` 或 `TASK_CANCEL`。`TASK_ACCEPT` 用于承接询问，`EXECUTE_CAPABILITY` 用于接受后的业务执行，二者共用步骤的 `commandId` 但以命令类型区分幂等键；取消仅表示请求结束当前业务任务，不是急停。`attemptNo` 初始为0，执行失败自动重试时为1；承接命令为0。命令接收端先做身份、schema、能力边界、安全字段、期限和幂等校验；随后返回 HTTP 202（已入队）或业务拒绝。承接结论另以 `TASK_RESPONSE` 上报，执行结果以 `EXECUTION_FEEDBACK` 上报。

### 3.2 状态上报

```json
{
  "reportType": "STATUS",
  "reportedAt": "2026-10-13T03:00:15Z",
  "status": {
    "onlineStatus": "ONLINE",
    "workStatus": "IDLE",
    "location": { "x": 120.5, "y": 88.2, "zone": "T2-B区" },
    "businessStatus": { "displayStatus": "IDLE" }
  }
}
```

`onlineStatus` 为 `ONLINE|OFFLINE`，`workStatus` 为 `IDLE|BUSY`。正常运行期间按档案周期上报，默认15秒；允许配置5—60秒。平台心跳默认30秒，配置范围10—120秒。状态只保存最新快照及必要事件，不持久化高频遥测流。

### 3.3 承接响应与执行反馈

```json
{
  "reportType": "TASK_RESPONSE",
  "reportedAt": "2026-10-13T03:00:02Z",
  "response": {
    "commandId": "CMD-20261013-000001",
    "accepted": true,
    "rejectReason": null
  }
}
```

```json
{
  "reportType": "EXECUTION_FEEDBACK",
  "reportedAt": "2026-10-13T03:00:03Z",
  "feedback": {
    "commandId": "CMD-20261013-000001",
    "attemptNo": 0,
    "executionResult": "SUCCESS",
    "reasonCode": null,
    "outputParams": {
      "displayStatus": "SUCCESS",
      "actualDuration": 30,
      "errorMessage": null
    }
  }
}
```

`executionResult` 为 `SUCCESS|FAILED|TIMEOUT`。失败时 `reasonCode` 必填；`attemptNo` 必须等于平台当前步骤尝试次数，旧尝试迟到反馈只记事件、不推进状态；同一尝试的重复反馈幂等。`outputParams` 必须匹配下表对应能力的输出结构。平台使用 `(agentCode, commandId, reportType, attemptNo)` 关联与去重。

### 3.4 统一响应

成功响应采用附录B通用包络 `{code:200,message:"success",data:{...}}`。schema错误使用参数错误码；未知设备/代理使用 4201/4204；能力越界使用 4302；不支持能力使用对应能力错误；运动安全字段使用 4106；命令超时使用 5003。具体 HTTP 状态码与错误码按附录B 3.2执行。

## 4. 内部代理统一消息

内部统一入口严格按附录B 4.1：

| `messageType` | 必要 payload | 结果 |
|---|---|---|
| `CAPABILITY_QUERY` | 可选 `capabilityType` | 已启用能力及模板摘要 |
| `STATUS_QUERY` | 无 | 代理最新状态和 `lastReportedAt` |
| `TASK_ACCEPT` | `taskId, stepSeq, capabilityType, inputParams` | 创建/发送承接命令，稍后由设备上报承接响应 |
| `TASK_REJECT` | `rejectReasonCode` | 归一化设备拒绝/无法承接结果 |
| `EXECUTION_FEEDBACK` | `executionResult, reasonCode, outputParams` | 校验并推进同一任务命令状态 |
| `TASK_CANCEL` | `taskId, stepSeq` | 向设备发送业务取消请求 |

每一消息关联唯一 `commandId`；重试复用原 ID。超时按需求只自动重试一次。每次请求校验代理启用/在线状态、能力已启用且属于类型边界、设备未被其它步骤占用、输入参数有效和安全字段白名单。任务执行器只调用统一代理消息网关；P1已移除原先固定返回成功的 `SimulatedAgentResponder`，设备上报进入统一报告服务推进状态。

## 5. 四类仿真配置和能力契约

公共约束：请求必须包含该设备类型支持的能力；缺必填字段、枚举不在范围内、数值越界、额外安全控制字段均拒绝且不执行。成功/失败均产出能力规定的 `outputParams`，并关联事件。仿真输入夹具和失败注入放在设备仿真配置中，不扩展业务命令 schema。

### 5.1 智慧航显 `SMART_DISPLAY`

支持：`CAP_INFO_DISPLAY`、`CAP_FLIGHT_UPDATE`、`CAP_NAVIGATION`。同一时刻仅一条展示内容，不支持触摸交互和 `CAP_NOTIFICATION`。

| 能力 | 输入约束 | 成功输出 | 可注入失败输出 |
|---|---|---|---|
| `CAP_INFO_DISPLAY` | `contentType=TEXT|IMAGE|VIDEO|HTML`；`contentData` 必填；`displayDuration` 5—300秒；`displayPosition` 可选 | `{displayStatus:"SUCCESS",actualDuration:<秒>,errorMessage:null}` | `TIMEOUT` 或 `DEVICE_ERROR`；含错误说明 |
| `CAP_FLIGHT_UPDATE` | 航班号、`updateType=DELAY|GATE_CHANGE|CANCEL`、变更内容；展示时长10—600秒 | `{publishStatus:"SUCCESS",publishTime:<ISO-8601>}` | `{publishStatus:"FAILED",publishTime:<ISO-8601>}` + `DEVICE_ERROR` |
| `CAP_NAVIGATION` | `targetLocation` 必填；`routePreference=SHORTEST|BARRIER_FREE` 可选 | `{routeGenerated:true,estimatedDistance:<米>,estimatedDuration:<秒>,waypointCount:<整数>}` | `{routeGenerated:false,...}` + `ROUTE_NOT_FOUND` |

样例：有效展示命令见 §3.1；无效示例 `displayDuration=2` 应参数拒绝；失败注入 `DEVICE_ERROR` 应有失败反馈且不标记任务步骤成功。

### 5.2 智能行李测量 `BAGGAGE_SCANNER`

支持：`CAP_BAGGAGE_MEASURE`、`CAP_OVERSIZE_ALERT`。仿真夹具包含合成行李长宽高、重量、是否放置；AUTO消费下一夹具，MANUAL等候夹具/手动触发。尺寸输出误差模拟需在±2cm内，重量误差在±0.5kg内。

| 能力 | 输入约束 | 成功输出 | 可注入失败输出 |
|---|---|---|---|
| `CAP_BAGGAGE_MEASURE` | `measureMode=AUTO|MANUAL`；`timeout=10..60`秒；有效执行预算≤30秒 | `{length,width,height,weight,isOversize,measureStatus:"SUCCESS"}` | `{measureStatus:"NO_OBJECT"}`、`{measureStatus:"TIMEOUT"}`；原因码对应 `NO_OBJECT`/`DEVICE_TIMEOUT` |
| `CAP_OVERSIZE_ALERT` | `baggageInfo` 必填，包含尺寸/重量；`alertLevel=WARNING|ERROR`；旅客信息仅允许合成数据 | `{alertId,reportStatus:"SUCCESS",reportTime:<ISO-8601>}` | `{alertId,reportStatus:"FAILED",reportTime:<ISO-8601>}` + `REPORT_FAILED` |

超规条件：三边之和大于158cm或重量大于32kg。边界用例158cm/32kg不超规；158.1cm或32.1kg超规。无效示例 `measureMode=CONTINUOUS` 应参数拒绝；异常事件生成后按当前系统事件/任务异常链路处理，不在仿真器内直接更改任务状态。

### 5.3 航延屏 `FLIGHT_DELAY_BOARD`

支持：`CAP_FLIGHT_UPDATE`、`CAP_INFO_DISPLAY`。优先展示航班变更，航班状态夹具支持定期刷新；刷新周期默认300秒。它不执行导航、陪同或语音通知。

| 能力 | 输入约束 | 成功输出 | 可注入失败输出 |
|---|---|---|---|
| `CAP_FLIGHT_UPDATE` | 同 §5.1，必须提供航班号、变更类型和内容；时长10—600秒 | `{publishStatus:"SUCCESS",publishTime:<ISO-8601>}` | `{publishStatus:"FAILED",publishTime:<ISO-8601>}` + `DEVICE_ERROR` |
| `CAP_INFO_DISPLAY` | 同智慧航显，时长5—300秒 | `{displayStatus:"SUCCESS",actualDuration:<秒>,errorMessage:null}` | `TIMEOUT` 或 `DEVICE_ERROR` |

有效示例：航班 `MU5101` 的 `GATE_CHANGE` 发布；无效示例缺 `flightNumber` 应拒绝；失败注入后上报失败且命令/事件仍可按 `commandId` 查询。

### 5.4 移动服务机器人 `MOBILE_ROBOT`

支持：`CAP_NAVIGATION`、`CAP_ESCORT`、`CAP_NOTIFICATION`、`CAP_INFO_DISPLAY`。位置通过状态上报中的 `location` 随仿真轨迹更新；禁入区域、最大单次业务距离500米由场景地图校验。SRS规定运动安全由设备本体控制，平台不发送安全控制参数；机器人仿真也不得接受此类参数。

| 能力 | 输入约束 | 成功输出 | 可注入失败输出 |
|---|---|---|---|
| `CAP_NAVIGATION` | 目标位置必填；路线偏好可选 `SHORTEST|BARRIER_FREE` | `{routeGenerated:true,estimatedDistance,estimatedDuration,waypointCount}` | 路线不存在/禁入目标返回 `routeGenerated:false` + `ROUTE_NOT_FOUND` |
| `CAP_ESCORT` | 目标位置；`escortMode=LEAD|FOLLOW`；`maxDuration=60..1800`秒 | `{arrivalStatus:"ARRIVED",actualDistance,actualDuration}` | `TIMEOUT` 或 `LOST_TARGET` + 相应原因码 |
| `CAP_NOTIFICATION` | `notificationType=VOICE|TEXT|BOTH`；内容必填；`repeatCount=1..5` | `{notificationStatus:"SUCCESS",actualRepeatCount}` | `{notificationStatus:"FAILED",actualRepeatCount}` + `DEVICE_ERROR` |
| `CAP_INFO_DISPLAY` | 同智慧航显 | `{displayStatus:"SUCCESS",actualDuration,errorMessage:null}` | `TIMEOUT` 或 `DEVICE_ERROR` |

有效示例：引导至 `GATE_A05`、无障碍路线偏好；无效示例 `maxDuration=30`、`repeatCount=6` 均拒绝；异常样例 `LOST_TARGET` 触发执行失败恢复链路。

### 5.5 `CAP_SIM_STATUS`

仿真体核心测试能力输入为 `simulatedCapability`、`simulatedResult=SUCCESS|FAILED|TIMEOUT`、可选 `simulatedDelay`（默认500ms）。输出 `simulationStatus:"SIMULATED"` 和所选业务能力的 `returnedData`。此能力仅用于仿真/测试环境；被模拟设备的业务任务仍使用继承来的能力编码。

## 6. 仿真生命周期、幂等和故障模型

- 设备生命周期：`STOPPED → STARTING → ONLINE/IDLE ↔ ONLINE/BUSY → OFFLINE`；禁用/归档由平台设备代理控制，不由仿真进程自行解除。
- 命令生命周期：`RECEIVED → ACCEPTED|REJECTED → RUNNING → SUCCEEDED|FAILED|TIMED_OUT|CANCELLED`。
- 重复 `commandId`：返回已存储的接收/执行状态，不重复改变设备状态或生成第二个业务事件。
- 故障注入类型：拒绝承接、执行失败、执行超时、无行李对象、报告失败、机器人丢失目标、仿真进程停止上报、恢复上报。每个注入须有适用能力、有效时间/次数、操作者和自动清除条件。
- 通用原因码：`DEVICE_ERROR`、`DEVICE_TIMEOUT`、`NO_OBJECT`、`REPORT_FAILED`、`ROUTE_NOT_FOUND`、`LOST_TARGET`、`BINDING_CONFLICT`。错误文字可本地化，逻辑依赖稳定原因码。
- 仿真设备只产生状态、业务结果及事件。最终任务是否成功、是否换设备/重规划/转人工，由平台任务编排和监督服务决定。

## 7. 安全与数据边界

- 上行和下行使用每设备唯一令牌，支持吊销/轮换；响应中不回显令牌。日志只记录凭据引用/脱敏标识。
- 对上行主体校验令牌所绑定的 `deviceCode` 和 `agentCode`，禁止一个实例冒充另一个实例。
- 解析 JSON 后递归检查禁止字段：`speed`、`velocity`、`acceleration`、`pose`、`waypoints`/低层路径点、`obstacleAvoidance`、`emergencyStop`、`speedLimit`、`safeStopOnDisconnect` 等；命中即拒绝并记录错误码4106。
- 旅客/航班数据仅用合成样例；不得将真实姓名/证件号加入仿真夹具、日志或长期事件。

## 8. P0阶段验收清单

| 编号 | 验收项 | 通过标准 | 本阶段核对方式 |
|---|---|---|---|
| P0-01 | 四类设备覆盖 | 四种类型与各自能力集合和附录F矩阵一致；仿真设备类型与被模拟类型区分清楚 | 对照附录F 3、6节逐项核对 |
| P0-02 | 能力参数覆盖 | 所有继承业务能力输入、输出、枚举/范围、成功/失败至少一例；行李超规阈值精确 | 对照附录F 2节及SRS 8.4 |
| P0-03 | 上下行接口闭环 | 健康握手、代理绑定、状态/承接/执行报告、命令下发各自方向和身份清楚 | 契约序列核查，不依赖不存在的代理ID |
| P0-04 | 统一入口与旧接口关系 | 附录B内部六消息归一到一个代理 service；旧路由只做兼容适配 | 对照附录B 4.1及当前 DeviceAgentController |
| P0-05 | 可靠性规则 | commandId 全局唯一且重试沿用；幂等；最多自动重试一次；状态/命令超时明确 | 对照SRS 5.5、附录B错误码 |
| P0-06 | 安全边界 | 独立设备鉴权、凭据不回显、安全字段拒绝、旅客数据合成 | 对照SRS 5.2.3/5.2.5及附录B错误4106 |
| P0-07 | 文档可机读 | 机器契约文件为有效 JSON，类型/消息/能力列表可由脚本校验 | JSON解析及静态一致性校验 |
