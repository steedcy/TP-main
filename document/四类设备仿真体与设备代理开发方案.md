# 四类设备仿真体与设备代理开发方案

- 文档状态：实施方案与阶段结论（P5于2026-10-14完成；最终系统验收仍受外部依赖限制）
- 日期：2026-10-14
- 项目：智慧机场人工智能集群协同服务平台（TIP）
- 目标：在无实体设备接入条件下，以四类仿真体支撑设备接入、能力调用、状态变化、任务执行与端到端演示，并列明需求规格说明书当前实现状况及后续路线。

## 1. 方案摘要

P0—P4已建立统一设备消息契约、设备令牌认证与握手、独立仿真运行时及四类类型化驱动、配置管理员控制台、设备事件/命令摘要和5秒态势快照轮询。P5完成SRS F001—F028差距映射、当前环境可运行的验证、权限/审计/异常分支复核及部署文档修订。当前通过的是已运行的自动化测试与前端构建，不代表附录E或SRS 8.2整体验收；本机PostgreSQL认证未通过，Redis基础PING通过但平台未能启动，规划/监督模型未配置；性能压测、长稳等项目仍待验收。

建议将**设备代理作为平台统一设备业务接口与状态归一化边界**，将**仿真运行时作为独立可启停的设备侧进程**。模拟进程按选定设备类型加载一个设备驱动，周期性向平台上报状态，接收业务命令并通过现有任务响应/执行反馈入口回传结果。四类实体设备的模拟配置均使用 `SIMULATOR` 设备类型并强制填写 `simulatedDeviceType`；能力依据所模拟类型继承。平台规划只看到统一的设备代理和被继承的能力，不需要感知具体模拟器内部实现。

开发应先固定通信契约和设备状态/命令模型，再打通一类设备的完整纵向链路，随后复用仿真运行时补齐其余三类。演示控制台提供设备启停、故障注入和当前状态观察，保证成功、拒绝、超时、离线恢复及异常恢复场景可重复呈现。

## 3. 现状与问题判断

### 3.1 已有基础

- Spring Boot + PostgreSQL/Flyway + MyBatis 后端；Vue 前端已有设备、代理、能力、类型边界、基线模板、任务、异常、态势等页面。
- 设备档案可关联虚实类型，仿真体可选择模拟设备类型；代理具备启停、状态、工作状态、当前任务和心跳超时处理。
- 五类设备能力边界和模板已有数据模型、服务、接口与管理页；仿真类型的能力继承已有代码处理。
- 任务编排包含任务响应和执行反馈入口，仿真设备会在下发后由 `SimulatedAgentResponder` 自动接受并固定成功。
- 任务异常恢复、基线模板试运行、计划校验、风险规则、操作记录等已有实现骨架。

### 3.2 关键缺口

P1—P4已逐步收口初始差距：固定成功的任务内自动应答器已删除；设备连接测试执行受令牌保护的运行时健康握手；统一消息入口和兼容适配共享代理服务；态势按REST快照轮询，不再依赖未实现的WebSocket；四类驱动支持类型化输入输出和受限故障场景。现阶段的主要未闭环项是数据库持久化/迁移、外部服务依赖、附录E全链路与非功能测试、角色全量越权验收，以及目标部署环境的启动/恢复演练，逐项状态见P5矩阵。

## 4. 目标架构

```text
任务规划 / 执行 / 基线干跑
             │ 统一业务消息、commandId
             ▼
      平台设备代理服务
      ├─ 能力/状态查询与候选筛选
      ├─ 参数边界与安全字段校验
      ├─ 命令关联、幂等、超时与事件记录
      └─ 设备协议适配器接口
             │ 设备统一通信契约
             ▼
       仿真运行时（独立进程）
       ├─ 注册的仿真设备实例与心跳调度
       ├─ 命令路由、命令队列与执行状态机
       ├─ 可控延迟、随机种子、故障注入
       └─ 类型驱动（四类设备各自的能力实现）
```

### 4.1 推荐模块边界

- **平台设备接入/代理层**：沿用 `device`、`devicetype` 领域模型；增加统一命令 DTO、设备接口认证、命令适配器、commandId 状态/去重、执行超时和设备事件落库。任务编排只调用代理服务，不直接调用模拟器或厂商协议。
- **仿真运行时**：建议作为单独可运行模块/进程（同仓库独立 Gradle/Maven 子模块或独立 Spring Boot 应用均可，优先复用 Java DTO/契约）。本地部署可由现有启动脚本一起拉起；仿真进程异常退出时平台应通过心跳将其转离线。
- **设备驱动**：接口统一为 `initialize(config)`、`accept(command)`、`execute(command)`、`cancel(commandId)`、`snapshot()`。每种设备独立校验输入并生成类型化输出；公共运行时处理通信、时序和生命周期。
- **演示控制面**：在后台增加仿真实例及场景控制入口，调用平台受控 API 启停/暂停仿真器、设置延迟、选择执行结果、触发离线/恢复/设备异常和配置场景数据。控制接口与设备上报接口分离，不能以管理端“直接改在线状态”代替上报链路。
- **前端**：设备/代理列表明确标注仿真实例及模拟类型；态势页面展示位置和在线/工作状态；设备详情展示最近命令、结果、仿真事件及连接状态。场景控制页面负责演示准备与故障注入，不混入旅客任务页面。

## 5. 设备通信与数据契约

### 5.1 统一消息种类

对齐附录B 4.1/5.2：能力查询、状态查询、任务承接请求、任务拒绝、执行反馈、任务取消；所有下发命令含全局唯一 `commandId`，同一命令重试复用原 ID。命令最小公共字段为 `agentId, commandId, taskId, stepSeq, capabilityType, inputParams, issuedAt, deadline`。反馈包括 `accepted/executionResult/reasonCode/outputParams/reportedAt`。状态包括 `onlineStatus, workStatus, location, currentCapability/currentCommand（可选）, reportedAt`。

### 5.2 通信实现建议

- **状态/反馈上行**：仿真运行时定时 `POST` 平台设备侧上报 API；任务接受和执行完成分别回传。心跳周期遵循设备档案配置（默认15秒），连接测试必须收到一次有效状态响应；平台按默认30秒（配置10—120秒）判断离线。
- **命令下行**：第一期采用仿真进程可访问的 HTTP 命令接收端点，由平台设备适配器向实例的登记端点发送；如本地网络/部署不适合回调，可将同一消息封装为 WebSocket 双向通道，但不同时维护两套业务语义。端点与传输协议由设备登记信息配置，统一命令 DTO 不依赖传输方式。
- **接口兼容**：对附录B的 `/device-api/v1/...` 契约和当前 `/api/v1/device-agents/...` 实现建立单一规范 DTO；可保留现有入口为兼容适配，不允许新代码绕过统一 service。将最终路径、方向、鉴权方式与错误码写入接口文档/OpenAPI。
- **鉴权**：仿真实例凭据单独签发、仅允许本实例上报/反馈，支持轮换/吊销；敏感值只保存引用或哈希，不进入日志。连接测试验证身份、代理映射和有效状态包。
- **可靠性**：commandId 幂等；重复命令不得重复执行副作用；命令/响应状态持久化并可查；网络错误按附录B/SRS规定最多自动重试一次；超时、拒绝、取消和迟到反馈均进入设备事件/任务事件并由任务监督流程处理。
- **安全边界**：消息白名单只接收业务意图和业务参数。对速度、加速度、姿态、底层路径点、避障、急停、限速、失联停靠等字段统一拒绝并记事件，仿真体同样执行该检查。

### 5.3 能力和结果契约

| 类型 | 能力类型 | 输入重点 | 仿真输出/事件 |
|---|---|---|---|
| 智慧航显 `SMART_DISPLAY` | `CAP_INFO_DISPLAY`、`CAP_FLIGHT_UPDATE`、`CAP_NAVIGATION` | 内容类型/内容/展示时长/位置；航班号及变更；目标位置和路线偏好 | 展示/发布状态、实际时长、错误信息；导航是否生成、距离/时长/路径点数 |
| 智能行李测量设备 `BAGGAGE_SCANNER` | `CAP_BAGGAGE_MEASURE`、`CAP_OVERSIZE_ALERT` | 自动/手动测量、超时；行李数据、阈值/告警级别 | 长宽高/重量、是否超规、测量状态；告警 ID、上报状态和时间 |
| 航延屏 `FLIGHT_DELAY_BOARD` | `CAP_FLIGHT_UPDATE`、`CAP_INFO_DISPLAY` | 航班号、延误/登机口变更/取消、变更内容、展示时长 | 发布/展示状态、时间、失败原因 |
| 移动服务机器人 `MOBILE_ROBOT` | `CAP_NAVIGATION`、`CAP_ESCORT`、`CAP_NOTIFICATION`、`CAP_INFO_DISPLAY` | 目标位置、路线偏好；陪同模式/时限；通知类型/内容/次数 | 路线结果；到达/超时/目标丢失、距离/时长；通知状态/实际次数；位置随时间变化 |

四类模拟对象均是 `SIMULATOR` 类型实例，仿真能力 `CAP_SIM_STATUS` 与被模拟类型能力边界分开管理；调度使用继承来的业务能力。仿真输出应遵循附录F参数范围和枚举值，不以通用 `{completed:true}` 代替能力结果。

## 6. 仿真行为与演示场景

### 6.1 通用状态机

`STOPPED → STARTING → ONLINE/IDLE → BUSY → ONLINE/IDLE`；停机或心跳超时进入 `OFFLINE`，恢复心跳回到在线；禁用、归档状态由平台控制。任务命令状态为 `RECEIVED → ACCEPTED/REJECTED → RUNNING → SUCCEEDED/FAILED/TIMED_OUT/CANCELLED`。运行时重启后需恢复未决命令，至少对已接收命令返回原状态，防止重放副作用。

### 6.2 可重复仿真控制

- 每实例可配置心跳周期、执行延迟、输出场景/固定值或随机种子。
- 每条命令可注入成功、设备拒绝、执行失败、超时、无对象、目标丢失、网络中断等结果；注入项设置范围和自动清除时间，避免长期污染演示。
- 设备级可控制停止上报、恢复上报、移动机器人位置轨迹、行李尺寸重量、航班变更内容。
- 每次注入记录操作者、设备、命令/任务、注入类型、起止时间和结果，演示后可一键恢复默认场景配置。

### 6.3 端到端演示路径

1. 创建四类 `SIMULATOR` 档案，选择模拟类型、区域、坐标和上报周期；连接测试经真实模拟进程握手通过后创建代理。
2. 四类实例按周期上报，代理状态和位置进入候选资源池及态势展示。
3. 执行典型任务：航班变更（航延屏发布→航显引导→机器人通知/引导）、超规行李（测量→告警）、特殊旅客（航显会合提示→机器人陪同）。
4. 在控制台注入步骤失败/代理离线，观察候选设备切换、异常记录、局部重规划或待人工处理；恢复仿真器后观察代理重新上线。
5. 通过任务详情、代理事件、命令记录和操作日志回放完整因果链。

## 9. P5收口结果与剩余验收

已完成的阶段功能以P1—P4验收记录和源码为证。P5自动化测试只覆盖矩阵列明的组件/HTTP范围，不能代替附录E整体验收。目标环境准备后按矩阵和部署手册继续执行：Flyway全部迁移与持久化事务；Redis会话/过期；模型、监督服务成功/超时/拒绝；角色越权与日志脱敏；10并发任务/20设备心跳压测；8小时运行、重启恢复、备份恢复和浏览器现场验收。

## 10. 主要风险与处理

- **平台集成依赖未就绪**：本机PostgreSQL端口可达但默认账号认证失败，Redis基础PING正常而应用未启动，模型服务未配置；本次不对数据库迁移、平台会话和模型集成作通过结论，按P5矩阵步骤复验。
- **附录E未整体执行**：已运行的测试证明组件行为与仿真协议往返，不证明部署、性能、长稳或所有业务流程通过。
- **移动机器人安全边界**：仅模拟业务结果与位置变化，不模拟/控制真实运动安全系统；禁止安全控制字段沿统一校验路径进入命令。
- **候选设备排序权重**：需由产品/测试确认业务权重后按已记录步骤复验，不把默认实现当成已确认需求。
