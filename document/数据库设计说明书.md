## 1. 数据库概述

### 1.1 数据库选型

| 项目 | 说明 |
|---|---|
| 关系型数据库 | PostgreSQL 15.x |
| 缓存数据库 | Redis 7.2.x |

说明：本项目为演示/验证性质单机部署（对应SRS_NF013），不引入时序数据库与对象存储组件；不涉及视频/图片等大文件存储需求。

### 1.2 数据库命名规范

| 对象类型 | 命名规范 | 示例 |
|---|---|---|
| 数据库名 | 小写字母+下划线 | airport_ai |
| 表名 | 小写字母+下划线，复数形式 | users, tasks, devices |
| 字段名 | 小写字母+下划线 | user_id, created_at |
| 主键 | id | id |
| 外键 | {关联表}_id | user_id, task_id |
| 索引 | idx_{表名}_{字段名} | idx_tasks_status |
| 唯一约束 | uk_{表名}_{字段名} | uk_users_username |

### 1.3 通用字段约定

| 字段名 | 类型 | 说明 | 必填 |
|---|---|---|---|
| id | BIGINT | 主键，自增 | 是 |
| created_at | TIMESTAMP | 创建时间，默认CURRENT_TIMESTAMP | 是 |
| updated_at | TIMESTAMP | 更新时间，默认CURRENT_TIMESTAMP | 是 |
| created_by | VARCHAR(64) | 创建人用户名 | 否 |
| updated_by | VARCHAR(64) | 更新人用户名 | 否 |

说明：任务事件表（task_events）为仅追加表，不适用通用的updated_at/软删除约定，见4.7节单独说明。

## 4. 数据表设计

### 4.1 用户认证模块

#### 4.1.1 users（用户表）

**表说明**: 存储系统账号信息，字段范围按TBD-06拍板结论（用户名/密码/角色/启用状态/姓名/联系方式/创建时间/最后登录时间）设计，并纳入密码锁定字段

| 字段名 | 类型 | 长度 | 允许NULL | 默认值 | 说明 |
|---|---|---|---|---|---|
| id | BIGINT | — | 否 | AUTO_INCREMENT | 主键 |
| username | VARCHAR | 32 | 否 | — | 账号，唯一，1~32位 |
| password_hash | VARCHAR | 255 | 否 | — | 密码哈希（加盐摘要，不可逆） |
| real_name | VARCHAR | 32 | 否 | — | 姓名 |
| role | VARCHAR | 32 | 否 | — | 角色：SYSTEM_ADMIN/OPERATOR/CONFIG_ADMIN（对应系统管理员/运行操作员/配置管理员） |
| contact | VARCHAR | 128 | 否 | — | 联系方式（手机号或邮箱） |
| status | VARCHAR | 16 | 否 | ACTIVE | 账号状态：ACTIVE/INACTIVE/LOCKED |
| failed_login_attempts | INT | — | 否 | 0 | 连续登录失败次数 |
| locked_at | TIMESTAMP | — | 是 | — | 账号锁定时间 |
| locked_reason | VARCHAR | 255 | 是 | — | 锁定原因 |
| last_login_at | TIMESTAMP | — | 是 | — | 最后登录时间 |
| last_failed_login_at | TIMESTAMP | — | 是 | — | 最后失败登录时间 |
| created_at | TIMESTAMP | — | 否 | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | — | 否 | CURRENT_TIMESTAMP | 更新时间 |
| created_by | VARCHAR | 64 | 是 | — | 创建人 |

**DDL语句**:

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(32) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    real_name VARCHAR(32) NOT NULL,
    role VARCHAR(32) NOT NULL,
    contact VARCHAR(128) NOT NULL,
    status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    failed_login_attempts INT NOT NULL DEFAULT 0,
    locked_at TIMESTAMP,
    locked_reason VARCHAR(255),
    last_login_at TIMESTAMP,
    last_failed_login_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(64),
    CONSTRAINT chk_users_status CHECK (status IN ('ACTIVE', 'INACTIVE', 'LOCKED')),
    CONSTRAINT chk_users_role CHECK (role IN ('SYSTEM_ADMIN', 'OPERATOR', 'CONFIG_ADMIN'))
);

CREATE UNIQUE INDEX uk_users_username ON users(username);
CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_users_role ON users(role);
```

说明：不单独设会话表，会话状态由Redis维护（空闲30分钟失效，对应SRS_NF002，详见附录A第4.3节），不落库持久化。

CREATE TABLE devices (

    connection_test_status VARCHAR(16) NOT NULL DEFAULT 'UNTESTED',

CREATE TABLE device_agents (

## 5. 索引设计

### 5.1 索引设计原则

1. **主键索引**：所有表使用BIGSERIAL自增主键，自动创建主键索引
2. **唯一索引**：业务唯一键（如账号、设备编码、规则编号）创建唯一索引
3. **外键索引**：所有外键字段创建索引，提升关联查询性能
4. **查询索引**：高频查询字段（如状态、时间）创建普通索引

### 5.2 核心索引清单

| 表名 | 索引名 | 索引类型 | 索引字段 | 说明 |
|---|---|---|---|---|
| users | uk_users_username | UNIQUE | username | 账号唯一索引 |
| users | idx_users_status | NORMAL | status | 按状态筛选（如查询已锁定账号） |
| devices | uk_device_code | UNIQUE | device_code | 设备编码唯一索引 |
| device_agents | uk_device_agent_device | UNIQUE | device_id | 一设备一启用代理约束 |
| device_capabilities | uk_device_cap_code | UNIQUE | device_id, capability_code | 设备能力唯一索引 |
| tasks | uk_task_code | UNIQUE | task_code | 任务编号唯一索引 |
| tasks | idx_task_status | NORMAL | status | 按状态查询任务（工作台9种状态统计） |
| plan_versions | uk_plan_version_no | UNIQUE | task_id, version_no | 任务内版本号唯一 |
| task_events | idx_task_event_task_id | NORMAL | task_id | 按任务查询事件时间线 |
| operation_logs | idx_op_log_created_at | NORMAL | created_at | 按时间查询日志 |

## 8. 数据库性能优化

### 8.1 查询优化建议

1. **避免全表扫描**：WHERE条件字段建立索引
2. **分页查询优化**：使用LIMIT OFFSET时，先查询ID再关联详情
3. **JSON字段查询**：PostgreSQL支持JSON索引（GIN索引），对plan_versions.plan_steps等高频查询JSON字段可按需添加
4. **时间范围查询**：created_at、occurred_at字段建立索引

### 8.2 连接池配置

对齐附录C第6.2节单机部署规模：

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 最小连接数 | 5 | 保持活跃连接 |
| 最大连接数 | 30 | 按≤10并发用户+后台任务估算 |
| 连接超时 | 30s | 获取连接超时时间 |
| 空闲连接回收 | 600s | 10分钟未使用则回收 |

### 8.3 定期维护任务

| 任务 | 频率 | 说明 |
|---|---|---|
| VACUUM | 每周 | 清理死元组，回收空间 |
| ANALYZE | 每天 | 更新统计信息，优化查询计划 |
| 慢查询分析 | 每周 | 分析pg_stat_statements，优化慢SQL |

说明：本项目首期不做任务事件、操作记录的自动清理（对应TBD-08拍板结论），故不设自动化数据归档/删除任务；如后续投入长期运行环境需重新评估。
