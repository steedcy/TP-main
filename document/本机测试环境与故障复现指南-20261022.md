## 二、启动与检查

在项目的 tip 目录打开PowerShell。以下操作不需要输入API Key或设备令牌：

```powershell
.\scripts\manage-local-test.ps1 -Action Start
.\scripts\manage-local-test.ps1 -Action Frontend
.\scripts\manage-local-test.ps1 -Action Status
```

Start启动已经构建好的后端和已登记的六个仿真体；当前服务已运行时先检查状态，避免重复启动。Frontend单独启动管理页面。运行时记录和日志在 .local-test，默认不进入版本管理。

后端默认连接真实Kimi。MOONSHOT_API_KEY从已有用户或系统环境变量读取；无须粘贴到聊天中。数据库环境变量及设备凭据加密密钥也必须保留。

需要重新登记/补齐能力及重新试运行模板时，使用 scripts/local-test-environment.py configure。它复用设备档案和设备令牌，不重复创建设备；每次重新配置模板会产生新版本并重新试运行。脚本依赖的Python位置为：

```text
C:\Users\savy\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe
```

修改源码后应先停止本项目服务、重新构建，再启动；Windows运行中的JAR会被锁定，不能直接覆盖。

## 三、设备故障条件

下面以航班信息屏为例。后台可以看到状态和相关任务事件。每组测试前后恢复 success、online、heartbeat、delay:1000。

```powershell
# 主动报告离线，再恢复
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode offline
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode online

# 停止心跳，不主动报告离线：验证30秒阈值及10秒扫描周期
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode silent
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode heartbeat

# 实际返回失败、实际返回TIMEOUT、完全不返回执行反馈
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode failed
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode timeout
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode no_feedback

# 恢复成功；调整执行延迟，供取消试运行验证使用
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode success
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode delay:10000
.\scripts\manage-local-test.ps1 -Action DeviceFault -Device SIM_F2_FLIGHT -Mode delay:1000
```

no_feedback必须用平台的步骤超时事件判断；不能把设备主动返回TIMEOUT当作平台检测超时通过。模板步骤超时允许10～600秒，默认60秒；扫描每10秒运行，因此观察时间包含扫描偏差。无反馈导致的平台超时后，应取消该设备当前业务占用；试运行失败处理会自动发送取消指令。

行李测量仪还支持 no_object，机器人支持 lost_target。仅对支持该场景的设备使用。故障控制接口使用该设备令牌认证，脚本自动从本机加密存储中取得。

## 四、模型故障条件

真实Kimi用于正常规划和实际调用质量验证。故障替身仅用于稳定重复触发异常，不作为真实模型准确性、服务稳定性或在线性能证据。

1. 启动替身：manage-local-test.ps1 -Action ModelFixture。
2. 编辑 .local-test/planning-fault.json。goal、planning、replanning分别控制目标理解、首次规划、局部重新规划；delaySeconds默认为65秒。
3. 切换后端到替身：manage-local-test.ps1 -Action UseFaultModel。该操作会重启后端，应避开8小时稳定性测试窗口。
4. 执行相应用例，检查超时/错误、计划校验、降级或人工状态、设备命令是否被禁止。
5. 恢复真实Kimi：manage-local-test.ps1 -Action UseKimi。不修改系统持久环境变量，不更换或复制API Key。

示例配置：

```json
{"goal":"success","planning":"success","replanning":"timeout","delaySeconds":65}
```

可选模式：success、failure、unavailable、timeout、malformed、too_many_steps、safety、low_confidence。请求记录在 .local-test/planning-requests.jsonl，不保存HTTP认证头。

本次对替身端点验证了正常响应、失败码、HTTP503、非法JSON和客户端等待超时。正式用例仍需在切换后的完整业务流程中验证各分支；不能用端点验证代替TC-034/038/046/060～062整条用例通过。

## 五、地图和测试数据

F2为1260×6895像素，原点位于左下角；页面转换为 x/1260、(6895-y)/6895。设备位置使用F2_TEST虚构区域。F2_SERVICE_POINT=(810,4200)、F2_BAGGAGE_POINT=(805,4050)、F2_TEST_GATE=(815,4600)。GATE_A05只是用于兼容现有仿真测试的同坐标别名，不代表真实登机口已完成标定。

这些点用于业务位置展示和测试，不是物理通行路径、安全边界或导航精度验收数据。机器人模拟移动在已配置测试地标之间插值；未知地标不再被随机映射为坐标。需要真实登机口位置结论时，须补充人工确认的真实标定点。

航班号TEST1022、旅客协助描述、行李尺寸80×55×35cm和重量35kg均为虚构测试数据。当前两台测量仿真体启动为超规样本；正常行李分支须在独立场景把仿真测量值换为55×40×20cm、10kg并重新启动对应实例，不改变生产判定阈值。
